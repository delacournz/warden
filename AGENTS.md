# Warden

> `warden` CLI: machine-wide leasing of iOS sims, Android emulators, ports and app builds for agents/users. Bun + Turborepo monorepo. Apps in `apps/*`, shared packages in `packages/*`. Usage: [README.md](README.md). Plan: [docs/plans/wdn-warden-cli.md](docs/plans/wdn-warden-cli.md).

## Stack / Dependencies

- Bun (package manager, runtime, test runner)
- Turborepo (task orchestration)
- TypeScript (strict) via `@delacour/warden-tsconfig`
- Biome (lint + format) via `@delacour/warden-biome-config`
- prek (git hooks: biome check on commit, typecheck on push)

  e2e/                # @delacour/warden-e2e — spec runner (test/expect over bun test), iOS/Android driver, warden-simd helper, devtools; see packages/e2e/AGENTS.md
  e2e-bench/          # @delacour/warden-e2e-bench — private benchmark of warden/maestro/argent/agent-device/tester.army/detox on one parity suite; `bun run bench`; see packages/e2e-bench/AGENTS.md

## Key Patterns

- Every package/app `biome.jsonc` uses `"extends": "//"`; rules only live in `packages/biome-config/root.jsonc`.
- Packages extend `@delacour/warden-tsconfig/tsconfig.base.json` (composite); apps set `composite: false`.
- React code extends `tsconfig.react.json`.
- Errors returned as `Result` / `AsyncResult` discriminated unions from `@delacour/warden-types/result`.
- sqlite `BEGIN IMMEDIATE` (`store.transaction`) is the cross-process mutex — no lockfiles.
- Never shut down / erase / install on a device warden didn't create or lease (foreign = read-only).
- Only `@delacour/warden`, `@delacour/warden-<target>` and `@delacour/warden-e2e` are published to npm, from manifests generated by `apps/cli/scripts/npm-packages.ts` (node shim + per-platform binary packages + the bundled spec API), lock-step version. Every workspace `package.json` stays `private`.
- Versions of `@delacour/warden` / `@delacour/warden-e2e` are owned by changesets (`.changeset/`); never edit `version` by hand.
- Side effects (`exec`, clock, pid liveness, stdin, spawn) are injected; tests use temp `WARDEN_HOME`.
- A CLI change (command, flag, default, error code, config key, spec API, MCP tool) updates `skills/warden/` in the same PR: `.claude/rules/skill-sync.md`; `apps/cli/src/skill-coverage.test.ts` fails on an undocumented command or flag.

## Docs analytics (apps/docs)

PostHog only, off unless `VITE_POSTHOG_TOKEN` (`phc_…`) and `VITE_POSTHOG_HOST` (`https://i.delacour.co.nz`) are set at **build** time; Railway sets them per environment (prod `warden.co.nz`, staging `staging.warden.co.nz`). delacour-monorepo declares them (`wardenAnalyticsEnv` in `.railway/analytics.ts`, used by `apps/warden/infra/railway.ts`, with a per-env `DEPLOY_ENV` so prod and staging never share an image): the same token every Delacour app uses, so each environment's PostHog project (cookieless mode enabled) holds every site: warden's events carry `site: "warden"` and `surface: "web"|"server"` (`SUPER_PROPERTIES` in `posthog.ts`). `i.delacour.co.nz` is PostHog's managed reverse proxy (DNS-only CNAME, attached to no Railway service); from `warden.co.nz` it is third-party, so strict blocker modes may drop events (PostHog's proxy limit rules out an `i.warden.co.nz`). Dev and CI set neither and render no analytics. `turbo.jsonc` lists `VITE_*` on `build` (strict env mode) and a test holds it to that. Cookieless until the visitor accepts the banner (`cookieless_mode: "on_reject"` + `opt_out_capturing_by_default`); Accept turns on the cookie, local storage and session replay (inputs masked, recorder bundled from `posthog-js/dist/recorder`, never loaded from outside). Heatmaps on; autocapture and surveys off in code (`apps/docs/src/lib/analytics/posthog.ts`). One stored answer (`consent.analytics` in localStorage) in `consent.ts`, the banner in `components/consent-banner.tsx`, reopened by the footer's cookie settings. `/privacy` renders `src/lib/privacy.ts`, and `privacy.test.ts` holds its claims to the code (installed packages, the SDK options, the CLI's update hosts). Events: `$pageview`, `$$heatmap`, `$snapshot`, `outbound`, `download`, `copy`, `search` from the browser, and `agent-fetch` from the server for `/llms*.txt` and `.md` reads (`src/lib/analytics/server.ts`, called from `start.ts`). Only counted hosts report, so a prod build on `localhost` sends nothing.

## Design systems (`@delacournz/ui`, `@delacournz/apogee`)

`apps/docs` lists both design systems from delacour-monorepo as optionalDependencies (GitHub Packages, `@delacournz` scope in `bunfig.toml`; CI installs with the `NPM_READ_TOKEN` secret, a tokenless clone skips them). **Installed, not yet used** — nothing imports their CSS or components.

- `@delacournz/ui` — the "site" design system (Base UI + shadcn base-lyra, Tailwind v4). CSS: `@import "@delacournz/ui/styles";`
- `@delacournz/apogee` — the "app" design system (coss on Base UI, Orbit palettes, Phosphor icons, Tailwind v4). CSS: `@import "@delacournz/apogee/styles.css";`
- **Never load both in one document**: they define the same shadcn tokens (`--primary`, `.dark`, …) with different values. Pick one per page/app.
- The CSS entry declares its own `@source`, so the single `@import` in the Tailwind v4 stylesheet (`apps/docs/src/styles/app.css`) is all a migration needs.
- Peers: `react` / `react-dom` ^19.2, `tailwindcss` ^4. Web (React DOM) only — never add them to `apps/example` (Expo) or the CLI/packages.
- Until a migration is planned, the docs site's current UI (`fumadocs-ui` + `apps/docs/src/components`) stays the source of truth, and `apps/example/src/components/ui` (React Native) is unaffected.

## Rules

1. Route context for shared data — fetch in `beforeLoad`, read via `useRouteContext()`
2. TanStack Query is the cache — no global state stores
3. No barrel exports — import directly from source files
4. Colocate tests next to source
5. TDD — failing test first, run `bun test <path>`
6. No `any` — use discriminated unions
7. Biome for lint + format
8. prek hooks — biome on commit, typecheck on push

## Signoff (local CI)

PRs into `develop` are gated on local signoff, not GitHub Actions. Branch protection requires one commit status, `signoff`, written by [basecamp/gh-signoff](https://github.com/basecamp/gh-signoff) from the authoring machine.

- Agents: `.claude/rules/signoff.md` is the always-on rule (sign off after `gh pr create` and after every push to an open PR), the `signoff` skill (`.claude/skills/signoff`) is the procedure, and a `PostToolUse` hook in `.claude/settings.json` reminds after a PR is opened or a head moves.
- One-off per machine: `gh extension install basecamp/gh-signoff`.
- With the PR open, a clean tree and HEAD pushed: `bun run signoff` (`-- --dry-run` previews the plan). It diffs against the PR base, runs every applicable check from `scripts/signoff/signoff-checks.ts` (typecheck, check, test always; `native` when `packages/e2e/native/**` changed), writes `signoff/<check>` per pass, then the `signoff` umbrella, and posts one report comment naming the actor and runner (agents show as agents).
- A status binds to a SHA: every push (or **Update branch**) drops it, so re-run.
- A failing check is work to fix, never a reason to skip. `--only` / `--skip` write the passed sub-contexts but never the umbrella.
- Can't run a check here (no Mac/Xcode for `native`)? Dispatch the real thing from CI, which writes the same statuses: `gh workflow run ci --ref <branch> -f signoff-sha=$(git rev-parse HEAD)`. Review fork code before dispatching.
- Never bare `gh signoff` (it attests without running anything) unless the user explicitly asks; say so in the PR if you do.
- New always-on check: add it to `signoff-checks.ts` and the `signoff` job in `.github/workflows/ci.yml` (a drift test enforces it). Never make a path-gated context required.

## Releasing

- `develop` is the default + integration branch; feature PRs target it. `main` is a release pointer only `.github/workflows/promote.yml` moves, always a fast-forward to a develop commit. Never push `main`.
- A PR that changes what `@delacour/warden` / `@delacour/warden-e2e` ship adds a changeset (`bun changeset`, pick `@delacour/warden` only; e2e follows via `fixed`). Docs/internal-only PRs need none. Agents: follow `.claude/rules/changesets.md` and the `changeset` skill (`.claude/skills/changeset`).
- Each push to `develop` runs `version.yml`: opens/updates the "🔖 chore(release): vX.Y.Z" PR, titled with the next version (bumps, CHANGELOGs, `bun.lock`), and dispatches `ci.yml` so it gets `signoff`.
- Merging the version PR triggers `promote.yml`: fast-forward `main`, push tag `v<version>`. Railway production builds `main`, staging builds `develop`.
- The docs deploy as a Docker image from `apps/docs/Dockerfile` (repo-root context, root `.dockerignore`): Nitro's `.output` plus a vendored `@delacournz/otel-start` bundle on `oven/bun:*-slim`, no workspace `node_modules`. The Railway service (`warden-docs`: builder, `dockerfilePath`, watch patterns, variables, domains) is declared in `delacournz/delacour-monorepo`'s `apps/warden/infra/railway.ts`. A Dockerfile build sees a variable only when it is an `ARG`, so a new `VITE_*` needs one there; a new workspace dependency of `apps/docs` needs adding to that service's `watchPatterns`, or pushes touching it are skipped.
- The tag triggers `release.yml`: GitHub Release with binaries + npm publish via OIDC trusted publishing (`release` environment, no token, no reviewer click).
- The same tag builds the desktop viewer (`apps/viewer`, `viewer` job: darwin-arm64, darwin-x64 on the Mac runner, win32-x64 on `windows-latest`). `warden-viewer-<target>.tgz` assets ride the GitHub Release and are merged into `SHA256SUMS`; they are not npm packages. macOS is signed with the hardened runtime and notarized when the `APPLE_*` secrets are set, Windows is Authenticode-signed when `WINDOWS_CERTIFICATE*` are set; without them the build is unsigned with a `::warning::`. Secret list: `apps/viewer/AGENTS.md` § Release.
- `bun run release <version>` (`apps/cli/scripts/release.ts`) is break-glass only, for when CI is down. It bypasses changesets.

## Checklists

### Adding a package
1. `packages/{name}/package.json` named `@delacour/warden-{name}` with `fmt`/`lint`/`check`/`typecheck`/`test` scripts
2. `tsconfig.json` extending `@delacour/warden-tsconfig/tsconfig.base.json`
3. `biome.jsonc` with `"extends": "//"`, `"root": false`
4. `bun install`, then `bun run typecheck && bun run check`
