# Warden

> `warden` CLI: machine-wide leasing of iOS sims, Android emulators, ports and app builds for agents/users. Bun + Turborepo monorepo. Apps in `apps/*`, shared packages in `packages/*`. Usage: [README.md](README.md). Plan: [docs/plans/wdn-warden-cli.md](docs/plans/wdn-warden-cli.md).

## Stack / Dependencies

- Bun (package manager, runtime, test runner)
- Turborepo (task orchestration)
- TypeScript (strict) via `@delacour/warden-tsconfig`
- Biome (lint + format) via `@delacour/warden-biome-config`
- prek (git hooks: biome check on commit, typecheck on push)

```

  docs/               # @delacour/warden-docs — Fumadocs + TanStack Start docs site (content/docs/*.mdx), :3210
  example/            # @delacour/warden-example — Expo + Delacour UI demo app; `@delacour/warden-e2e` specs run via `warden e2e example`
packages/
  core/               # @delacour/warden-core — lease store, allocation, device providers, build cache
  e2e/                # @delacour/warden-e2e — spec runner (test/expect over bun test), iOS/Android driver, warden-simd helper, devtools; see packages/e2e/AGENTS.md
  e2e-bench/          # @delacour/warden-e2e-bench — private benchmark of warden/maestro/argent/agent-device/tester.army/detox on one parity suite; `bun run bench`; see packages/e2e-bench/AGENTS.md
  biome-config/       # shared Biome config (root.jsonc, react.jsonc)
  tsconfig/           # shared tsconfig (tsconfig.base.json, tsconfig.react.json)
  types/              # shared utility types (Result, AsyncResult, ok, err)
scripts/              # repo scripts (pre-commit biome, signoff/ = local CI gate)
```

## Key Patterns

- Every package/app `biome.jsonc` uses `"extends": "//"`; rules only live in `packages/biome-config/root.jsonc`.
- Packages extend `@delacour/warden-tsconfig/tsconfig.base.json` (composite); apps set `composite: false`.
- React code extends `tsconfig.react.json`.
- Errors returned as `Result` / `AsyncResult` discriminated unions from `@delacour/warden-types/result`.
- sqlite `BEGIN IMMEDIATE` (`store.transaction`) is the cross-process mutex — no lockfiles.
- Never shut down / erase / install on a device warden didn't create or lease (foreign = read-only).
- Only `@delacour/warden`, `@delacour/warden-<target>` and `@delacour/warden-e2e` are published to npm, from manifests generated by `apps/cli/scripts/npm-packages.ts` (node shim + per-platform binary packages + the bundled spec API), lock-step version. Every workspace `package.json` stays `private`.
- Versions of `@delacour/warden` / `@delacour/warden-e2e` are owned by changesets (`.changeset/`); never edit `version` by hand.
- Side effects (`exec`, clock, pid liveness, stdin, spawn) are injected; tests use temp `WARDEN_HOME`.

## Rules

1. Route context for shared data — fetch in `beforeLoad`, read via `useRouteContext()`
2. TanStack Query is the cache — no global state stores
3. No barrel exports — import directly from source files
4. Colocate tests next to source
5. TDD — failing test first, run `bun test <path>`
6. No `any` — use discriminated unions
7. Biome for lint + format
8. prek hooks — biome on commit, typecheck on push

## Signoff (local CI)

PRs into `develop` are gated on local signoff, not GitHub Actions. Branch protection requires one commit status, `signoff`, written by [basecamp/gh-signoff](https://github.com/basecamp/gh-signoff) from the authoring machine.

- One-off per machine: `gh extension install basecamp/gh-signoff`.
- With the PR open, a clean tree and HEAD pushed: `bun run signoff` (`-- --dry-run` previews the plan). It diffs against the PR base, runs every applicable check from `scripts/signoff/signoff-checks.ts` (typecheck, check, test always; `native` when `packages/e2e/native/**` changed), writes `signoff/<check>` per pass, then the `signoff` umbrella, and posts one report comment naming the actor and runner (agents show as agents).
- A status binds to a SHA: every push (or **Update branch**) drops it, so re-run.
- A failing check is work to fix, never a reason to skip. `--only` / `--skip` write the passed sub-contexts but never the umbrella.
- Can't run a check here (no Mac/Xcode for `native`)? Dispatch the real thing from CI, which writes the same statuses: `gh workflow run ci --ref <branch> -f signoff-sha=$(git rev-parse HEAD)`. Review fork code before dispatching.
- Never bare `gh signoff` (it attests without running anything) unless the user explicitly asks; say so in the PR if you do.
- New always-on check: add it to `signoff-checks.ts` and the `signoff` job in `.github/workflows/ci.yml` (a drift test enforces it). Never make a path-gated context required.

## Releasing

- `develop` is the default + integration branch; feature PRs target it. `main` is a release pointer only `.github/workflows/promote.yml` moves, always a fast-forward to a develop commit. Never push `main`.
- A PR that changes what `@delacour/warden` / `@delacour/warden-e2e` ship adds a changeset (`bun changeset`, pick `@delacour/warden` only; e2e follows via `fixed`). Docs/internal-only PRs need none.
- Each push to `develop` runs `version.yml`: opens/updates the "🔖 chore(release): vX.Y.Z" PR, titled with the next version (bumps, CHANGELOGs, `bun.lock`), and dispatches `ci.yml` so it gets `signoff`.
- Merging the version PR triggers `promote.yml`: fast-forward `main`, push tag `v<version>`. Railway production builds `main`, staging builds `develop`.
- The tag triggers `release.yml`: GitHub Release with binaries + npm publish via OIDC trusted publishing (`release` environment, no token, no reviewer click).
- `bun run release <version>` (`apps/cli/scripts/release.ts`) is break-glass only, for when CI is down. It bypasses changesets.

## Checklists

### Adding a package
1. `packages/{name}/package.json` named `@delacour/warden-{name}` with `fmt`/`lint`/`check`/`typecheck`/`test` scripts
2. `tsconfig.json` extending `@delacour/warden-tsconfig/tsconfig.base.json`
3. `biome.jsonc` with `"extends": "//"`, `"root": false`
4. `bun install`, then `bun run typecheck && bun run check`
