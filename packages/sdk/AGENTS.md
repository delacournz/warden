# @delacour/warden-sdk

Typed client (`createWardenClient`), ops (`src/ops/*`), plugins, ai-sdk adapter, and the `--json` contracts.

## contracts (`src/contracts/*.schema.ts`)

Zod schema per `warden … --json` output; curated facade `@delacour/warden-sdk/contracts`, single files at `@delacour/warden-sdk/contracts/<name>`.
The CLI producers annotate their output with the inferred type (`const doc: LsJson = …`), so drift is a compile error. Tests `schema.parse` the real output.
The CLI imports these with `import type` only: zod must never load on a cold start (`apps/cli/src/startup.test.ts`).

## CLI dogfooding: per command

The CLI never goes through `createWardenClient` for lease commands (it would load zod, drivers, plugins on every start). Both sides call the same lower-level engine functions instead; shared logic lives in light modules here.

| Command | Shared path |
|---|---|
| `ui *` | `src/ops/*` directly (CLI = argv + rendering adapter) |
| `claim`, `run` | `leasing/claim-request` (`claimWithRequest`, `claimedJson`) |
| `release` | `leasing/device-shutdown` + `device-lease` (`releaseLeases` in `core.ts` is the same sequence) |
| `ls`, `devices` | `src/lease-view.ts` (`withLeaseState`, `aliveDeviceLeases`; also used by `client.ts`) |
| `port` | `leasing/ports` (`claimPorts`, `releasePorts`) |
| `app`, `dev` | `builds/prepare`, `leasing/dev-session` |
| `check`, `gc`, `queue`, `capacity` | store / leasing helpers; CLI-only views |

## Publishing (`@delacour/warden-sdk`)

The workspace package stays `private`; the published `@delacour/warden-sdk` is generated by `apps/cli/scripts/npm-packages.ts` (`stageSdk` in `apps/cli/src/npm/sdk-stage.ts`), lock-step with `@delacour/warden`. `release.ts` writes the version into `packages/sdk/package.json` too and publishes the SDK after the platform packages.

- **Bundle**: `bun build --target bun`, ESM, workspace packages inlined, `zod` + `ai` external (`sdk-bundle.ts`). Declarations: tsc emit via `declarations.ts` with `esmExtensions` so it resolves under node16 and bundler.
- **Public exports** (`SDK_ENTRIES` in `manifests.ts`): `.`, `./ai-sdk`, `./ai-sdk/tools.schema`, `./plugins`, `./plugins/conformance`, `./contracts`. Everything else in this package's own `exports` (`./client`, `./ops/*`, `./lease-view`, `./sdk.types`) is workspace-internal; `lease-view` is CLI plumbing and is deliberately not published. A new public entry = a new `SDK_ENTRIES` row + manifest test.
- **Dependencies**: `zod` from this `package.json`, `ai` as an optional peer (same range as here), exact `optionalDependencies` on every `@delacour/warden-<target>` so `warden-simd` resolves (`locate-helper` last rung: `platform-package`).
- **Gate**: `apps/cli/src/npm/sdk-stage.test.ts` stages the real package and runs bundle-safety, `publint --strict` and `attw --profile esm-only`. The profile ignores node10 and CommonJS on purpose: the package is ESM and Bun-only.
- **Stage and pack alone** (no platform binaries needed): `bun run --cwd apps/cli build:npm:sdk -- --out <dir>`, then `npm pack` in `<dir>/warden-sdk`.
- Bare `@delacour/*` specifiers must never reach the output (the test fails): add any new workspace package to `WORKSPACE_PACKAGES` in `declarations.ts`.
