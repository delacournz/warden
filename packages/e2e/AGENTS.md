# @delacour/warden-e2e

warden's own mobile e2e stack (plan: `docs/plans/wdn-e2e.md`). No lease / build code here (that's `packages/core`); no CLI code (that's `apps/cli`, which imports from here).

## Layout (`src/`)

| Dir | Purpose |
|---|---|
| top level | `index.ts` (the published entry), `env.ts` (`WARDEN_*` names + `readEnv`), `errors.ts`, `session.ts` (process-wide session, `globalThis`), `preload.ts`, `app.ts` / `device.ts` / `device-devtools.ts` / `fixtures.ts` / `fixture-session.ts` (the `app`, `device`, `screen` fixtures) |
| `driver/` | `Driver` contract (`driver.types.ts`, **frozen interface** shared by every layer), errors, refs, hash settle, `typing.ts` (the one text/key pacing path, shared with `warden ui`), `alerts.ts` (optional `alertOn(backend)` / `isFrontmost(bundleId)` capabilities, iOS only), `open.ts`; `ios/` (`warden-simd` NDJSON client + `xcrun simctl` ops), `android/` (persistent `adb shell` + uiautomator), `driver.testing.ts` (FakeDriver) |
| `runner/` | `test`/`describe`/hooks over `bun:test`, attempts, `results.jsonl`, artifacts |
| `screen/` | locator query model, roles, text matching, actions, polling, text render + selector parser (shared with `warden ui`), `field.ts` (fill/clear/confirm a text field) |
| `expect/` | `expect` wrapper + locator matchers |
| `devtools/` | Metro inspector discovery, Hermes CDP, console/network/React tree. Metro's inspector proxy 401s a debugger upgrade without an `Origin`: `openCdp` sends `http://127.0.0.1:<port>` (`localhost` is accepted, then the socket is dropped with 1006). `reloadJs` = `expo.reloadAppAsync` → `DevSettings` → `POST /reload` (only if neither exists); `Page.reload` freezes bridgeless hosts, `DevSettings.reload` is a no-op under expo-dev-launcher; no epoch change = `reload_failed` |
| `flows/` | `.flow.json` schema, record, replay, export |
| `native/` | `warden-simd` Swift package on idb's library package (`native/ios`), scripts (`deps`, `build`, `smoke`, `fake-simd`) |

## Publishing
Published as `@delacour/warden-e2e` (manifest from `apps/cli/src/npm/manifests.ts`, staged by `build:npm`) in lock-step with `@delacour/warden`; this `package.json` stays `private`.
- Public surface is `src/index.ts` (`.`) and `src/preload.ts` (`./preload`), bundled by `Bun.build` (`apps/cli/src/npm/e2e-bundle.ts`) into `index.mjs` / `preload.mjs` + one shared chunk: workspace packages inlined, `bun:test` and `zod` external. Everything else (`driver/*`, `env`, `runner/results`, ...) is workspace-private; `apps/cli` is compiled separately and imports it from the workspace, so it is deliberately not in the package `exports`.
- Declarations come from the TypeScript compiler API (`apps/cli/src/npm/declarations.ts`): `types/**` holds what the two entries reach, workspace imports rewritten to relative paths; `index.d.ts` / `preload.d.ts` re-export it. A type the public API exposes must be reachable from the entries. Consumers need `moduleResolution: bundler` (Bun's default) and `@types/bun`.
- A new third-party runtime import must be added to `E2E_EXTERNALS` and this package's `dependencies` (the bundle test fails on any bare import other than `zod`).

## Tracing (`runner/trace.ts`, `runner/span.ts`)
`trace.jsonl` holds `step-start` / `step-end` (what the console prints) and trace-only `span` lines `{type:"span", ts, op, ms, ok, code?, detail?}`: `ts` is when the call **started** (epoch ms), a span is written when it ends (so file order is not `ts` order), `ok:false` carries the error `code`.
- `op` names the layer: `driver.<call>` (every `Driver` call, incl. `driver.app.<call>` and optional capabilities; `driver/traced-driver.ts`, a `Proxy` that `session.driver()` returns), `device.<call>` (`traced-device.ts`, wired in `fixtures.ts`), `read.<call>` (`Locator` reads, detail `{locator}`).
- Code deep in a call leaves scalars for its span with `noteSpanDetail` / `addSpanDetail` (`driver/span-detail.ts`, an `AsyncLocalStorage`; a no-op outside a span): adb time/count (`adbMs`, `adbCalls`), the dump route (`dumpRoute`, `dumpRoutesTried`, `dumpMs`), settle `via`/`reason`. `session.span(op, fn, { detail?, verdict? })` is the same thing for any other call; it just runs `fn` outside an attempt.
- `Driver["settle"]` stays `{quiet, waitedMs}` (frozen contract); drivers answer the wider `SettleDetail` of `driver/settle.ts` (`via`: `stream | snapshot | hash`, `reason`, `frontmostPid`; iOS passes the helper's reply through; Android says `snapshot` when one dump covered `quietMs` and `hash` when it compared dumps, and so does the iOS hash fallback (`hash`); a late helper answer is `reason: "helper_timeout"`), `settleDetailOf` reads it back off the narrow type, and `device.settle()` returns it. Both settle spans carry it as `detail`.
- Spans are buffered (`SPAN_BUFFER_MAX`) and appended before the next step event or by `TraceWriter.flush()` when the attempt ends; no `appendFileSync` per RPC. Arguments are never recorded (`typeText` carries passwords).
- The bench's `untracedMs` per test (`packages/e2e-bench/src/adapters/parse/warden-results.ts`) is the test wall time that no step and no span covers; anything that shows up there is a call nobody wrapped.

## Rules
- Never run real `simctl` / `adb` / `warden-simd` in `bun test` — inject `Exec`, use `driver.testing.ts` / `native/scripts/fake-simd.ts`. Smoke scripts live in `native/scripts` and are run by hand.
- `Result` / `AsyncResult` from `@delacour/warden-types/result`; `DriverResult<T>` = `AsyncResult<T, DriverError>`.
- Import files directly (`@delacour/warden-e2e/driver/open`), no barrels except the published `src/index.ts`.
- Do not change `driver/driver.types.ts` or the `WARDEN_*` names in `env.ts` without updating `docs/plans/wdn-e2e.md` — other agents build on them.
- Tests colocated (`*.test.ts`), TDD, no `any`.
- Flow export goldens live in `src/flows/export.golden/*.e2e.ts` (biome-ignored, typechecked by `tsc`); regenerate with `UPDATE_GOLDEN=1 bun test src/flows/export.test.ts` and review the diff.

## Android driver internals (`src/driver/android`)
One resident `adb shell` per driver; every snapshot is a `uiautomator dump` (~1.9 s: JVM start plus its own `waitForIdle(1000, 10000)`).
- **Settle** is one dump (`quiet` unless it failed or took ≥ 10 s) for any `quietMs` ≤ 1 s; only a longer window compares successive dumps by hash. `driver/settle.ts`'s `settleByHash` is shared with iOS's fallback and `warden ui`, so Android's shortcut lives in `android-driver.ts`.
- **Per-serial state** (`android-state.ts`): `$WARDEN_HOME/android/<serial>.json` = `{sdk, dumpRoute, animations}`, written atomically and best effort (an unreadable or hand-edited file reads as empty; values are validated before they reach a shell). It is trusted only on the API level it was written on. `openDriver` supplies the file store; tests pass `memoryAndroidState()`, never the real home.
- **Dump route**: the saved route is tried first; with none, `tty` first from API 30 (`routeOrder` in `android-dump.ts`), else `stdout`. A saved route that fails re-probes the others and the route that worked is saved. `warden ui` also keeps its own `android-dump-route` file and passes it as `dumpRoute` (wins over the saved one).
- **Animation scales**: open reads `window/transition/animator` scales and sets them to 0 in one shell call; the values to restore (`planAnimations`) are saved in the state file, and `close` puts them back (an unset scale is `settings delete`d). A process that dies without closing leaves the originals in the file; the next driver on that emulator sees zeros plus saved originals and restores them on its close.
- **`openUrl`** is `am start -p <env.bundleId>`, so only the app under test can take a link.

## `device.alert` and `device.openLink` (`src/device.ts`, `alert-reader.ts`, `device-link.ts`)
- `alert()` reads the alert ONCE through the bridge (`alertOn("axbridge")`: a screen without an alert is one tree read, no sleeps; the bridge sees what apps show themselves, e.g. the Keychain "Save Password?" sheet, and the permission prompts captured in `Fixtures`). A modal with no readable buttons yet (`{buttons:[]}`) is looked at again 3 times, 200 ms apart. A failed one-reader read falls through at once to the two-reader `driver.alert()`, which retries transient failures (up to 13 reads, 100 ms apart). Android has no `alertOn`: its `alert()` is one uiautomator dump (`detectAlert` on it; the observation cache of PERF-2.1 will reuse a fresh one).
- `openLink()` (iOS): reads alerts every 100 ms for 1 s, then every 250 ms; reads inside the first 1.2 s ask only the host `ax` reader (SpringBoard-hosted sheets, never slowed by the bridge), the first read after it asks both readers and is the confirmation that no sheet is up. Early return needs that confirmation AND `driver.isFrontmost(env.bundleId)` true. Why `frontmost` and not `settle{bundleId, quietMs:0}`: `settle` waits, can restart the stream and only reports the pid on a mismatch. While another app is in front (or the driver / bundle id cannot say) the full `waitMs` (8 s) applies. A link that returned this way is remembered per session and URL scheme (https: per host): later calls skip alert reads for 1.2 s and return once the app is in front. A sheet is not memoised. `until` (a `Locator`) returns when visible with no sheet up; `waitMs` caps everything and never throws.
- Limits to keep in mind: a sheet that shows later than 1.2 s while the app is already in front is missed (the old fixed 8 s window caught it); `waitMs` / `until` are the way to wait longer. A link whose bundle is not `WARDEN_BUNDLE_ID` never reports the app in front and keeps the full wait.

## `warden-simd` internals (`native/ios/Sources/warden-simd`)
NDJSON over stdio or a unix socket (`~/.warden/simd/<udid>.sock`, `warden e2e` passes it as `WARDEN_SIMD_SOCKET`). The wire is `src/driver/ios/simd-protocol.ts`; Swift output is pinned by goldens in `Tests/warden-simdTests/Fixtures` (`WARDEN_SIMD_UPDATE_GOLDEN=1 swift test` rewrites them, `native/scripts/element-shape.test.ts` parses them with the zod schemas).
- **AX guests**: `Session.open` builds one `.exclusive` `axbridge` reader (a guest private to this helper, `automationMode: true`) plus a host `ax` reader for per-request fallback. A bridge failure with no explicit `backend` is retried on `ax`, with a `log` warn and `snapshot.fallback.reason`. A bridge answer of one childless area-less root is re-read once, then read on `ax` (`Session.recoverFromEmptyRoot`).
- **Quiescence stream** (`Ops/Settle.swift`, `QuiescenceMonitor`): one stream opened at helper start and kept for its life (the guest follows the frontmost app; ~0.5 s to open). `WARDEN_SIMD_STREAM_IDLE_S=<s>` closes it after that long without a `settle` (default off). Every stream spawns its own guest and two streams on one simulator leave each other stuck: one helper per leased sim. Measured with a second helper process on the same sim: reads stay correct in both, but `settle` falls back to snapshot stability (`via:"snapshot"`, ~2.5 s instead of ~260 ms) for as long as the other stream is open. Remedy: stop the stale helper (`warden ui close --udid <udid>`, or kill the `warden-simd --udid <udid>` process); `WARDEN_SIMD_STREAM_IDLE_S=1` on every helper only softens it (settles then reopen the stream, ~0.9 s, and still collide with a concurrently active one).
- **Relaunch repair**: with no stream bound, a relaunched app answers every `axbridge` read with `E_APP_NOT_RESPONDING`. `Session.readRecovering` opens a stream, waits for its first state (max 4 s), reads once more, then falls back to `ax`. First read after a relaunch: ~90 ms with the stream open, ~2 s when repaired.
- **Alerts / modal** (`Ops/Snapshot.swift`, `Session.topmostModal`): `alertButtons` and `snapshot.modal` pick the best container that holds a button, ranked alert/dialog (`Alert`, `_UIAlertController*` e.g. the Keychain "Save Password?" sheet, Safari `SFDialogView`, idb's named modal) > sheet > popover; ties go to the last in tree order. A tip popover never hides a dialog under it. App-owned prompts (Keychain, app alerts) are only visible on `axbridge`; `ax` reads such an app as one empty root. Debug params on `snapshot`: `raw:true` returns idb's document (source of `Fixtures/*.document.json`), `pid:<n>` reads that process instead of the frontmost app (SpringBoard pid: `xcrun simctl spawn <udid> launchctl list | grep SpringBoard`).
- **`alertButtons{backend?}`** (`Ops/Snapshot.swift`, `Session.answerAlert`): no `backend` reads both readers (`ax`, then `axbridge`: two tree reads when there is no alert). `backend:"ax"` or `"axbridge"` reads that reader only (one read; its failure fails the op). An `axbridge` read that finds idb's blocking modal but no container with a button answers `{buttons:[]}` (not `null`), so a caller can look again; the default read still answers `null` there. The TS side is `driver.alertOn(backend)` (`driver/alerts.ts`); `driver.alert()` stays the two-reader read.
- **`frontmost{bundleId}`** (`Ops/Snapshot.swift`) → `{frontmost, pid?, frontmostPid?}`: whether the bundle's launchd pid is the pid the quiescence stream last reported. No tree read and no wait, unlike `settle{bundleId}` it never restarts the stream or judges quiet. `frontmost:false` with no `frontmostPid` = no stream state yet (the op opens the stream). Needs the bridge (`E_UNSUPPORTED` otherwise, an old helper answers `E_BAD_REQUEST`); callers treat any failure as "cannot tell". The TS side is `driver.isFrontmost(bundleId)`.
- **`settle{quietMs=250, settleTimeoutMs|timeoutMs=3000, bundleId?}`** replies `{quiet, waitedMs, via, reason?, frontmostPid?}`. `via` is `stream` (guest reported run-loop idle + animations inactive for `quietMs`) or `snapshot` (stream stuck, two identical reads). `settleTimeoutMs` wins over `timeoutMs`. `bundleId` holds `quiet` back until the stream's frontmost pid is that bundle's process (`FrontmostGate`; the pid is re-resolved every 150 ms, and the stream is restarted only once the bundle has a pid the stream does not report, 500 ms after it appeared, then every 1.5 s, never while it is still opening or opened under 500 ms ago without a pid yet); at the deadline `quiet:false, reason:"frontmost_mismatch"`. A deadline is not an error. Needs `axbridge` (`E_UNSUPPORTED` otherwise; the TS side then polls hashes).
- **Key pacing** (`Ops/Keyboard.swift`): `key` / `typeText` take `paceMs` (quiet after each key, default 30), `holdMs` (down to up, 40), `repeatGapMs` (extra before a repeated key, 300), each 0..1000. `WARDEN_SIMD_PACE_MS` / `WARDEN_SIMD_HOLD_MS` / `WARDEN_SIMD_REPEAT_GAP_MS` change the defaults. A React Native field digests ~45-50 ms per key; faster loses characters. `driver/ios/type-budget.ts` sizes the request timeout.
- **`selectAll`** (`Ops/Keyboard.swift` `KeyboardMap.selectAll`, `Ops/Input.swift`): Cmd+A, held and paced like a key (`paceMs` / `holdMs` apply). `driver/typing.ts` `SelectsAll` / `canSelectAll` is the optional capability; `screen/field.ts` `focusAndClear` sends select-all plus one Backspace for plain text on a driver that has it (an empty field or a placeholder shown as the value gets no keys; secure fields are backspaced by their bullets, as they cannot be read back), and a fill that does not confirm retries with counted Backspaces (`ClearMethod` `counted`), for fields that refuse the shortcut. iOS reports `placeholder: null` for React Native inputs, so a plain field showing its placeholder is indistinguishable from one holding that text: it takes select-all, never one Backspace per placeholder character.
- **`health`**: `ax.bridge` is `available | missing | failed | degraded`. `degraded` + `ax.lastError {message, agoMs}` means the guest is present but the last read failed (the next good read clears it). `health{probe:true}` (what `--health` runs) reads through the bridge and reports `failed`. A fresh `--health` process has no read history, so `warden doctor` also asks the running helper's socket.
- **Tracing**: `--trace` or `WARDEN_SIMD_TRACE=1` logs one debug event per quiescence sample; `--verbose` logs more; the log file is `~/.warden/simd/<udid>.log`.
- **AutomationEnabled**: the bridge needs `com.apple.Accessibility` `AutomationEnabled`. `ios-driver.ts` reads the sim's plist with `plutil` (~10 ms) and only runs `simctl spawn defaults write` (300-500 ms) when it is not already true.
- **Non-public API** (breaks first on a new Xcode): `Simulator.defaultHIDTransport` (mirrored in `Session.negotiatedTransport`: DTUHID from CoreSimulator 1155.4, else Indigo), `SimulatorDeviceOrientation.hidOrientation` (mirrored in `Session.hidOrientation`), the CoreDevice orientation service (a failed read falls back to `OrientationMemory`, `source` `written` / `assumed`), plus idb's private CoreSimulator and Accessibility use.
- **After an Xcode update**: `bun run --cwd packages/e2e native:build`, `swift test --package-path packages/e2e/native/ios`, `dist/warden-simd --health --udid <udid>` (expect `ax.bridge=available` and the right `hid.transport`), then `bun native/scripts/smoke.ts --udid <udid>` on a leased sim with the example app (`--kill-bridge` / `--kill-helper` exercise recovery). `warden doctor` shows the idb and Xcode versions the helper was built with.
