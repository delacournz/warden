# @delacour/warden-e2e-bench

Benchmarks four mobile e2e frameworks (warden, argent, agent-device, tester-army) on the example app's 8-test parity suite (plan: `docs/plans/wdn-bench.md`; usage: `README.md`). Private, never published. No lease/build code here (that's `packages/core`); the suites drive the pinned bench app (`bench app build`, via `warden app ensure --variant bench`).

## Rules
- `bench run` never builds, fingerprints or calls EAS: it installs the pinned app from `.bench/app/<platform>/` after claiming the device. Rebuild with `bench app build --force`; `--eas` is only for `app build`.
- Never spawn in `bun test`: inject `Exec` (`fakeExec`). Never install global tools; `doctor` prints hints.
- Devices come from `warden claim --ttl 4h --label bench`, heartbeated every 60 s for the run; release exactly the lease ids claimed (never `--mine`). `--udid` reuses a lease and releases or heartbeats nothing: the caller must hold that lease.
- CPU headline = host CPU-seconds per rep (`RepResult.resources.cpuSeconds`: the timed `run` window only, warm median), from per-pid deltas of `ps time`. `ps %cpu` (`cpuAvgPct`/`cpuPeakPct`) is a decaying average on macOS and the framework-level `resources` are whole-framework (prepare … teardown): never judge a target on them.
- CPU-seconds bias (read before comparing frameworks): ticks see a process only while it is alive at a tick, so the CPU a process uses after its last tick, and processes that live entirely between two ticks, are missed. For every child the bench `run`s, the gap is closed at its exit: `ExecResult.cpuSec` (rusage, which includes the descendants it waited for) minus the last `ps time` of every process the ticks saw in its tree is charged as an `ExitCharge` at the exit time, booked to the root's group (so in the per-group split a descendant of another group, e.g. `bun test` under a `warden` root, has its unseen CPU under the root). Still missed: children the bench `start`s (daemons), processes a framework orphans or never waits for, and short-lived processes under pattern-matched daemons it did not spawn (a framework's own server), so a framework that fans out to many short `xcrun`/`adb` calls from such a daemon still reads low. Without a usable `time` column there are no CPU-seconds at all (absent, never 0; the sampler logs it once per framework).
- Reading the per-process table ("Where the CPU goes", `RepResult.resources.processes`, optional field, schema stays v1): rows are `processLabel` groups of the host tree and (iOS) the `launchd_sim` tree for the timed `run` window, top 12 per scope plus `other`; `shareOfScopePct` is of that scope's CPU-seconds. Bias: it is built from the same ticks, so a process that lives between two ticks is only seen through exit charges, which are separate host rows `"<label> (exit charge)"` (label = the root's `processLabel`, else its group) rather than folded into the root, so host rows sum to `resources.cpuSeconds`; `spawnCount` counts pids a tick saw, so short-lived `xcrun simctl` calls read low there. Idle processes under 1 MiB RSS are not written to a tick. RSS is a per-label sum per tick (0 where absent). Android `sim` has no per-process rows (`top` rows are totalled by name). Compare labels across runs with `bench compare`, never read one rep's single row as a rate.
- `ps time` resolution: macOS prints `M:SS.ss` (10 ms); procps (Linux hosts) prints `[DD-]HH:MM:SS`, whole seconds, so per-tick deltas on a Linux host are 0 or 1 s and only sums over many ticks (a rep, a framework) mean anything there. ps runs with `TZ=UTC LC_ALL=C` so `lstart` does not move with DST or the locale.
- Every suite must encode the same retries as `apps/example/e2e/helpers/steps.ts` (dropped first Next press, dropped first tab/row tap after sign-in, deep-link retry) so no framework gets an easier test. The warden suite writes them with warden's own options (`tap({ until })`, `app.open({ wait: "quiet" })`, `test.use({ systemAlerts })`, PERF-6.3: same 4 s window, two re-sends, 3 deep links of 6 s); the hand-rolled helpers that ran the published headline numbers are at `f05fee0`, and the other frameworks keep their own copies. Zero LLM, `retries=0`. Gaps a framework cannot express (argent checked state, agent-device retry) are documented in `README.md`, never papered over.
- A native test name missing from `suites/manifest.json` is a parity breach (framework `failed`, phase `run`); a manifest id absent from output is `missing`.
- Stop `warden-simd` before any other framework runs, and other daemons before warden (two AX clients on one sim collide).
- New framework or canonical test: update `adapter.types.ts` / `schema.ts`, `registry.ts`, `suites/manifest.json`, every `suites/<fw>/`, and the README + docs guide caveats. `bench doctor` fails a suite missing an id.
- tester-army needs Node `^22.22.3 || >=24.8`: `BENCH_NODE_BIN` / `--node-bin`. It keeps a private `AGENT_DEVICE_STATE_DIR` (`BENCH_TESTER_ARMY_STATE_DIR`).
- `Result` / `AsyncResult` from `@delacour/warden-types/result`; no `any`; no barrels; colocated tests; TDD.
- Report goldens live in `src/report/fixtures/` (helper `golden.ts`); regenerate with `UPDATE_GOLDEN=1 bun test src/report` and review the diff.
- CPU regression guard: `bench compare <A> <B> --max-cpu-regression 10%` exits 1 when warden's host cpu-s/rep (warm median, the docs headline) or host RSS peak (warm median of each rep's timed-window peak) in B exceed A's by more than the threshold, 2 when warden is not `ok` (or lacks a metric) on a side. A may be a baseline file (`baselines/*.json`, `baselineVersion: 1`); it then needs the flag and prints no diff. Refresh the baseline only from a new EAS run of the pinned bench app, never from a laptop run. The `cpu-guard` signoff check (`scripts/signoff/signoff-checks.ts`) runs it against `$WARDEN_BENCH_RUN_DIR` and skips with a printed line when that is unset; it only compares, never runs the bench.
- `bench merge <outDir> <runDir>... [--id ID]` joins per-framework EAS worker dirs into one run (ratios recomputed with `withRatios`, inputs copied to `<outDir>/workers/<framework>/`); it refuses a repeated framework or inputs that differ in platform or app sha256 (exit 2) and an `<outDir>` that already holds results.
