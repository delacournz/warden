# Accessibility: screen readers, audits, display settings

Check what a screen reader would say and in which order, audit a screen, read announcements, and set the OS accessibility settings an app reads. Verbs: `warden ui a11y …` (`ui.md`). Specs: `device.a11yAudit`, `device.screenReader`, `device.announcements`, matchers (`specs.md`). Suite defaults: `a11y` key (`suites.md`).

## Screen reader: what is real

| | iOS simulator | Android emulator |
|---|---|---|
| `a11y set --screen-reader` | a flag the app reads (`screenReader: { mode: "simulated", engine: "voiceover" }`); RN `isScreenReaderEnabled()` turns true; taps and snapshots are unchanged. VoiceOver does not run in the simulator | real TalkBack (`mode: "real", engine: "talkback"`); taps only move focus, so warden presses with accessibility actions |
| `a11y focus …` / `spoken` | `E_UNSUPPORTED` | works |
| `a11y order` / `speak` / `toAnnounce` | simulated speech | simulated speech |

Speech text is warden's model (`source: "simulated"`), an approximation of VoiceOver/TalkBack, never what they say. `spoken` is `source: "talkback"` only when TalkBack's verbose log is on, else composed from focus events (`simulated`). Keep a manual on-device pass for release.

TalkBack needs: an emulator with a Google Play image (TalkBack preinstalled; else `E_UNSUPPORTED … not installed`), the `warden-uiad` server (not `WARDEN_ANDROID_UIAD=0`; the `uiautomator dump` fallback unbinds TalkBack), and an unlocked screen. Turning it off (or release) puts the accessibility services and master switch back to what the device had.

## Settings (`warden ui a11y set`, `device.a11y({...})`)

All lease-scoped and undone on release. Each flag has a `--no-` form: `--no-bold --no-reduce-motion --no-screen-reader --no-reduce-transparency --no-button-shapes --no-differentiate-without-color --no-on-off-labels --no-high-contrast-text --no-color-inversion`.

| Flag / key | iOS | Android |
|---|---|---|
| `--text-size` / `textSize` | category or scale, live | scale (clamped 0.5-2) |
| `--bold` / `boldText` | live | `font_weight_adjustment` |
| `--contrast increased\|normal` | live | `skipped` |
| `--reduce-motion` / `reduceMotion` | live | `transition_animation_scale`: **off by default** (the driver restores the device value after zeroing its own scales); `true` zeroes it, which RN reads |
| `--reduce-transparency` `--button-shapes` `--differentiate-without-color` `--on-off-labels` | live `defaults` writes, no relaunch | `skipped` |
| `--high-contrast-text` `--color-inversion` | `skipped` | live |
| `--screen-reader` | simulated flag | real TalkBack |

A setting the platform has no mechanism for is `skipped` with a reason (a warning); only-skipped = `E_UNSUPPORTED`. `a11y status` shows what is recorded and the screen-reader state.

## Audit

`warden ui a11y audit` / `device.a11yAudit()` / `expect(device).toPassA11yAudit()` run warden's rules on the snapshot, plus the platform's own audit unless `--no-native` / `native: false`.

| Rule | Severity | WCAG | Finds |
|---|---|---|---|
| `missing-name` | error | 4.1.2 | a control a reader stops on with no accessible name |
| `image-no-name` | error | 1.1.1 | an image with no name (label it or mark it decorative) |
| `label-in-name` | error | 2.5.3 | visible text not contained in the accessible name |
| `target-size` | error | 2.5.8 | target under 24x24 with another target within 24 |
| `target-size-platform` | warning | | under 44pt (iOS) / 48dp (Android) |
| `duplicate-name` | warning | 2.4.6 | two controls announced the same |
| `role-in-name` | warning | | name repeats its role word ("Save button") |
| `hidden-focusable` | warning | | focusable but hidden, zero-size or off screen |
| `text-clipped` | warning | 1.4.4 | truncated/overflowing text; runs only from `accessibility-medium` up (`--text-size`, else the recorded one) |
| `native` | per engine | per engine | iOS: XCUITest `performAccessibilityAudit`; Android: ATF (contrast, touch target, labels) |

Fails at `--min-severity` (default `error`; `warning` also counts warnings). Suppress with `--ignore <rule[:identifier]>`; limit with `--rule <id>`. The native engine is skipped, never failed, when it cannot run (`skipped` in the result, a warning in the CLI): iOS needs the app running and the runner sources (checkout or the binary's embedded copy); a sim build is unsigned and cached.

## iOS needs the injected library

iOS hint, custom actions, reading order and announcements come from a library injected at app launch. Without it `snapshot --a11y`, `audit`, `order`, `speak` still work on the plain tree and warn; `announcements` and `toHaveHint` fail `E_UNSUPPORTED`.

- By hand: `warden ui open <bundle> --a11y` (relaunches once; remembered per device; `WARDEN_A11Y=1` does the same). Android needs nothing.
- Suites: `warden e2e --a11y`, or any suite with an `a11y` key (even `a11y: {}`), launches iOS apps with it. Other suites pay nothing.

## CLI

`warden ui a11y audit|order|speak|announcements|spoken|focus` and `snapshot -i --a11y`: flags, exit codes and output in `ui.md`.
