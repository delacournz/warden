## Improvement goal

Cut the time to boot a cold iOS simulator and a cold Android emulator to the point where the first test can start, make warm reuse across runs happen more often, and reduce probe/spawn counts on claim. This is the user's named interest: be exhaustive on this path, give per-step cost estimates, and state every trade-off (isolation vs speed, RAM vs warm pool) rather than picking for the user.

## Questions to answer with evidence

1. For each step above, the cost (measured where a comment or plan gives one, else estimated) and whether it is on the critical path to the first test.
2. Android: a warden-owned quick-boot snapshot per AVD (`-snapshot <name>` + `-no-snapshot-save` after a one-time warm save; or `-snapshot-load`), `-no-audio`, `-gpu swiftshader_indirect|host`, `-cores`, `-memory`: what each buys, what it risks (isolation across runs, read-only multi-instance constraints, ps16k images), and how warden would manage snapshot staleness (system-image hash). Also: `boot_completed` via `adb wait-for-device shell 'while [[ -z $(getprop sys.boot_completed) ]]; do sleep 0.2; done'` in one shell instead of a 2 s poll; `verifyWarm` for a reused emulator; the 1.5 s early-exit race.
3. iOS: the probe on a reused Booted device, `bootstatus -b` + `boot` ordering, golden pre-lock spawns, migration read per clone, setting `AutomationEnabled` (and slim's disabled set) in the golden so clones inherit it, a parallel reboot loop in headless, moving the hide out of the claim's critical path, `slim` cost vs benefit (what the 36 disabled daemons buy per test).
4. Warm reuse: what would let the second `warden e2e` run of the day start in seconds (keep-booted policy, `warden warm`/pre-boot, longer gc idle, helper residency), with the RAM cost per booted sim/emulator on a developer machine.
5. Throughput at N devices: `max = cores/4 ≤ 4`, 4 sims + 4 helpers + 4 spec processes on a 14-core host; whether the cap is right and where contention shows up in the bench numbers.
6. Robustness: a probe failure re-doing a cold boot up to 3 times; the Android `boot` existence race; a placeholder lease outliving a failed create; `hideSimWindows` rebooting a sim it did not shut down.
