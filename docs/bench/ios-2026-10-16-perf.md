Every warden test got faster (−23.6% to −56.7%; deep link −56.7%). The other frameworks moved −3.1% to +5.0%, so the host was comparable.

Read with care:
- **Prepare 708 ms** is a cold `warden-simd` start: the bench stops every framework's daemon between frameworks. Measured on the same sim, a cold `warden ui snapshot` is 544–726 ms and a warm one (resident helper, PERF-1.5) is 182–185 ms.
- **Host CPU avg 12.1%** is higher than 9.4% because the suite is 40% shorter; total CPU per rep went down. The bench runs `bun test` directly, so the `warden e2e` parent-process work (PERF-5.x) is not in this number.
- **Host RSS avg 149 MB** is up from 116 MB. The sampler has no per-process split yet; attributing it is a follow-up.
- agent-device had one failing test in one rep (95.8%), so it cannot set the pace in this run.

## Fairness rules

- Same `.app` for every framework (sha256 recorded above)
- Zero LLM calls
- Same assertions per canonical test id
- Same retry helpers (dropped first tap, dropped deep link, system alerts)
- Fresh app launch per test
- `retries=0`
- Frameworks run sequentially
- `caffeinate -dims` held for the run
- Warm medians exclude rep 1 (cold)
- Machine-readable reporters only
- Host otherwise idle; load average recorded
- Android `sim` counts the app and every framework's on-device helpers (uiautomator, instrumentation runners, Maestro, agent-device, Argent, warden-uiad), matched case-insensitively
- Host processes are tracked by pid and start time, so a reused pid is never counted
- Android animation scales are reset to the device's original values before every framework and restored at the end
