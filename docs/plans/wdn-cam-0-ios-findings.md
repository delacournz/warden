# WDN-CAM CAM-0 iOS spike findings

Spike code: `/private/tmp/claude-501/-Users-chris-orca-workspaces-warden-marron/28043c43-571b-4798-9aed-fce886d0866d/scratchpad/cam0-ios/` (`CamSpike.m` dylib, `CamApp.m` test app, `run.sh`, `out-*.txt`).
Run on iOS 27.x simulator (iPhone 17, leased via warden), arm64, dylib via `SIMCTL_CHILD_DYLD_INSERT_LIBRARIES`. iOS 27 needs scene lifecycle in the test app (UIApplicationSceneManifest) or it traps at launch.

## Verdict
Feasible with a **shadow session** design: swizzle at the `AVCaptureSession` / output level, never let the real session connect to the fake device. The "real session + fake device" path partly works but needs an open-ended set of private `AVCaptureDevice` selectors/KVO keys. Do not take it.

## Results per question

1. **Fake device** (`WCDevice : AVCaptureDevice`, `class_createInstance`, compile-time subclass works the same as allocateClassPair)
   - Returned from swizzled `+defaultDeviceWithMediaType:`, `+defaultDeviceWithDeviceType:mediaType:position:`, `+devicesWithMediaType:`, `+systemPreferredCamera`, `-[AVCaptureDeviceDiscoverySession devices]`: all fine. KVO add/remove on the discovery session fine.
   - `+[AVCaptureDeviceInput deviceInputWithDevice:error:]` **accepts the fake without any swizzle** and returns a real input with a real enabled video port. `canAddInput:` = YES.
   - Real `addInput:` then **throws** inside AVFCapture calling private device selectors. Peeled so far: `setCachesFigCaptureSourceConfigurationChanges:` (base throws "Not supported by this device"), `deviceFormatForSessionPreset:sourceVideoFormat:`, `_setActiveFormat:resetVideoZoomFactorAndMinMaxFrameDurations:sessionPreset:`, `_setVideoHDREnabled:forceResetVideoHDRSuspended:`, KVC `variableFrameRateVideoCaptureEnabled`, `flashSceneDetectedForPhotoOutput`. With stubs, addInput, addOutput (all four kinds), commit and startRunning (isRunning=1) did succeed, then `AVCapturePhotoOutput addConnection` KVO-observed another device key and crashed (NSNull boolValue). Whack-a-mole of private API, OS-version fragile. Rejected.
   - **Shadow path** (works end to end): swizzle `+[AVCaptureDeviceInput deviceInputWithDevice:error:]` and `-initWithDevice:error:` to return a `WCInput` (`class_createInstance`; overrides `device`, `ports` = @[]); swizzle session `canAddInput:`, `addInput:` (store input aside for fake, do not call real), `inputs`, `startRunning`, `stopRunning`, `isRunning`, plus `removeInput:`. Result: canAddInput YES, inputs=1, isRunning=1, no crash.
2. **Video data output**
   - `canAddOutput`/`addOutput:` works for video, photo, metadata, movie outputs on a real session with the shadow input (outputs=4). `setSampleBufferDelegate:queue:` works.
   - No real connection exists in shadow mode: `[output connectionWithMediaType:]` = nil, `layer.connection` = nil. Delivering synthetic `CMSampleBuffer`s (BGRA `CVPixelBuffer` -> `CMSampleBufferCreateReadyWithImageBuffer`) to `output.sampleBufferDelegate` on `output.sampleBufferCallbackQueue` with the real output as first arg works (6/6 delivered). Pass a connection via `[[AVCaptureConnection alloc] initWithInputPorts:@[] output:out]` (allowed, prints with null input) if consumers dereference it; vision-camera/expo-camera access `connection.videoOrientation` etc: nil-safe via nil messaging, a fake non-nil connection has `isVideoOrientationSupported` NO.
   - `startRunning` must be swizzled in shadow mode (it is the pump trigger); real one with a fake input crashes/throws.
3. **Photo**
   - `AVCapturePhoto` subclass (`class_createInstance`, override `fileDataRepresentation`, `pixelBuffer`, `metadata`, `CGImageRepresentation`, `timestamp`, `isRawPhoto`) works; consumer decodes the JPEG via `UIImage imageWithData`.
   - `AVCaptureResolvedPhotoSettings` subclass overriding `uniqueID`, `photoDimensions` works. Full sequence willBegin, willCapture, didCapture, didFinishProcessing, didFinishCapture delivered with no crash.
   - Real `-capturePhotoWithSettings:delegate:` throws ("No active and enabled video connection" / "processedFileType must be present in availablePhotoFileTypes"), so it must be swizzled. `AVCapturePhotoSettings photoSettings` is real and fine; the swizzle should read `settings.uniqueID` for the resolved id. `availablePhotoCodecTypes` / `availablePhotoFileTypes` are empty: swizzle if the app reads them (expo-camera/vision-camera may).
4. **QR / metadata**
   - `AVMetadataMachineReadableCodeObject` subclass (override `type`, `stringValue`, `bounds`, `corners`) delivered to an `AVCaptureMetadataOutput` delegate: OK, `isKindOfClass:` true, `-[AVCaptureVideoPreviewLayer transformedMetadataObjectForMetadataObject:]` returned the object unchanged.
   - Real `-setMetadataObjectTypes:` **throws** ("Unsupported type found") because `availableMetadataObjectTypes` is empty without a real input: swizzle `setMetadataObjectTypes:` (store) and `availableMetadataObjectTypes` (return a full list), `metadataObjectTypes`, `rectOfInterest` setters must not throw.
   - **Vision `VNDetectBarcodesRequest` does not work on the simulator**: default = Error 9 "Could not create inference context"; `usesCPUOnly = YES` runs but returned 0 results for the QR. **`CIDetector` (`CIDetectorTypeQRCode`) decoded "hello" from the CVPixelBuffer** (13-270 ms, first call slowest). Use CIDetector for QR (+ it returns `corners` via `topLeft/...`). Other symbologies: no sim-capable decoder tested (CIDetector is QR only); could ship ZXing-style fallbacks later or restrict v1 to QR. expo-camera itself uses ZXing for non-QR on frames.
5. **Preview layer**
   - `+[AVCaptureVideoPreviewLayer layerWithSession:]` with the shadow session: fine, `.connection` nil. Setting `layer.contents = CGImage` persists across stopRunning/startRunning, and the window snapshot rendered the image (also tried a sublayer). Per-frame `contents` assignment on the main thread (or CATransaction) is viable. Prefer a sublayer pinned to bounds with `contentsGravity` mapped from `videoGravity` (so resizeAspectFill is honoured), and an observer for `frame` changes. `captureDevicePointOfInterestForPoint:` returns the input point, `transformedMetadataObjectForMetadataObject:` identity: swizzle both if needed.
6. **Movie file output**: `AVAssetWriter` + `AVAssetWriterInputPixelBufferAdaptor` on the sim wrote a valid 30-frame H.264 mov (duration 1.00 s, 1 video track). Delegate `captureOutput:didFinishRecordingToOutputFileAtURL:fromConnections:error:` with `@[]` is callable. Real `startRecordingToOutputFileURL:recordingDelegate:`, `stopRecording`, `isRecording` throw/are false without connections: swizzle all three plus `didStartRecording` delegate. Feasible; CAM-9 (as planned).
7. **UIImagePickerController**: swizzling `isSourceTypeAvailable:` to YES for Camera works, `setSourceType:Camera` does not throw, `availableMediaTypesForSourceType:Camera` already returns `public.image`, and presenting it **shows Apple's real camera UI** on the iOS 27 sim (shutter, gray placeholder preview, flip, flash; see `picker.png`). Not tested: what the shutter returns to the delegate. Plan's own overlay (`warden-camera-shutter`) is safer than relying on the system UI; keep swizzle + replace presentation.

## Recommended swizzle list (CAM-2)
Class methods `AVCaptureDevice`: `defaultDeviceWithMediaType:`, `defaultDeviceWithDeviceType:mediaType:position:`, `devicesWithMediaType:`, `systemPreferredCamera` (getter), `userPreferredCamera` setter (no-op; expo-camera sets it), `authorizationStatusForMediaType:`/`requestAccessForMediaType:` untouched (TCC real).
`AVCaptureDeviceDiscoverySession`: `devices` (must filter by the session's position + deviceTypes: spike returned both cameras; position/types are not public ivars, so also swizzle `discoverySessionWithDeviceTypes:mediaType:position:` / `initWith...` to record them); keep KVO key `devices` KVO-compliant.
`AVCaptureDeviceInput`: `deviceInputWithDevice:error:`, `initWithDevice:error:` (-> `WCInput`; override `device`, `ports`, `isEqual`).
`AVCaptureSession`: `canAddInput:`, `addInput:`, `removeInput:`, `inputs`, `startRunning`, `stopRunning`, `isRunning`, `sessionPreset` accepts, keep real `canAddOutput:`/`addOutput:`/`beginConfiguration`/`commitConfiguration`; post `AVCaptureSessionDidStartRunningNotification` / `DidStop` and set KVO `running` yourself.
`AVCapturePhotoOutput`: `capturePhotoWithSettings:delegate:`, `availablePhotoCodecTypes`, `availablePhotoFileTypes`, `isFlashScene...` as needed.
`AVCaptureMetadataOutput`: `setMetadataObjectTypes:`, `availableMetadataObjectTypes`, `setRectOfInterest:` as needed.
`AVCaptureMovieFileOutput` (CAM-9): `startRecordingToOutputFileURL:recordingDelegate:`, `stopRecording`, `isRecording`.
`AVCaptureVideoPreviewLayer`: no swizzle strictly required; add the frame sublayer; swizzle `captureDevicePointOfInterestForPoint:`/`pointForCaptureDevicePointOfInterest:` if apps use tap-to-focus.
`UIImagePickerController`: `+isSourceTypeAvailable:` (Camera YES), `+isCameraDeviceAvailable:`, `+availableCaptureModesForCameraDevice:`, and replace presentation of source Camera with warden's overlay.
Device (WCDevice) overrides: `uniqueID`, `localizedName`, `modelID`, `position`, `deviceType`, `hasMediaType:`, `isConnected`, `lockForConfiguration:`/`unlockForConfiguration`, `hasTorch/hasFlash/isTorchAvailable/torchMode/setTorchMode:`, focus/exposure/zoom getters+setters (`videoZoomFactor`, `minAvailableVideoZoomFactor`, ...), `formats` / `activeFormat` (a real `AVCaptureDeviceFormat` cannot be created: apps reading `activeFormat.videoSupportedFrameRateRanges` or `highResolutionStillImageDimensions` will nil-crash; return nil/empty and test against vision-camera), `supportsAVCaptureSessionPreset:`, `isFocusModeSupported:` etc, `copyWithZone:` (return self), KVO-compliant setters so apps that observe do not crash.

## What libs use (sources found: expo-camera 57.0.6, expo-image-picker in `~/.bun/install/cache`; react-native-vision-camera not present anywhere on the machine, nothing in `apps/example/node_modules`)
expo-camera iOS (`ios/Common/DeviceDiscovery.swift`, `Current/CameraSessionManager.swift`, `CameraViewModule.swift`):
- Discovery: two `AVCaptureDevice.DiscoverySession(deviceTypes: allDeviceTypes (wide, ultra-wide, tele, dual, dualWide, tripleCamera, LiDAR), mediaType: .video, position: .back/.front)`, KVO observes `.devices`; reads `AVCaptureDevice.systemPreferredCamera`; sets `AVCaptureDevice.userPreferredCamera`; `AVCaptureDevice.default(.builtInWideAngleCamera, for: .video, position:)`, `default(for: .video)`, `default(for: .audio)` (mic: leave real/nil).
- Session: `AVCaptureDeviceInput(device:)`, `AVCaptureSession`, `AVCaptureVideoPreviewLayer`, `AVCapturePhotoOutput` (`AVCapturePhotoCaptureDelegate`, `AVCapturePhotoSettings`, `AVCaptureResolvedPhotoSettings`, `AVCapturePhoto`), `AVCaptureMovieFileOutput` (`AVCaptureFileOutputRecordingDelegate`), `AVCaptureMetadataOutput` (`AVCaptureMetadataOutputObjectsDelegate`), `AVCaptureVideoDataOutput` (`AVCaptureVideoDataOutputSampleBufferDelegate`, used for the ZXing barcode path), `AVCaptureConnection` (`videoOrientation`, stabilization), `AVCaptureDevice.RotationCoordinator` (iOS 17, built from the device: **will need a swizzle or fail when given the fake device**), `focusMode`.
- **Simulator trap**: `CameraViewModule.swift` has compile-time `#if targetEnvironment(simulator)` branches: `takePicture` / `takePictureRef` use a generated placeholder (`ExpoCameraUtils.generatePhoto 200x200`) **only when `AVCaptureDevice.default(for: .video) == nil`**, and `record`/`stopRecording` throw SimulatorNotSupported under the same check. With the fake default device those branches are skipped and the real photo/record path (our swizzles) runs. Good, but also means the DeviceDiscovery `#if !targetEnvironment(simulator)` empty-guard is irrelevant.
- expo-image-picker: UIImagePickerController (source Camera) via the swizzles above.
vision-camera (from memory, unverified here since no source on disk): `AVCaptureDevice.DiscoverySession` with many device types, `AVCaptureDeviceInput`, `AVCaptureSession`, `AVCaptureVideoDataOutput` + `AVCaptureAudioDataOutput` + `AVCapturePhotoOutput` + `AVCaptureMetadataOutput`, `AVCaptureVideoPreviewLayer`, heavy use of `AVCaptureDevice.Format` (fps ranges, ISO, zoom) and `AVCaptureConnection`; expect more device/format surface than expo-camera.

## Risks / infeasible
- `AVCaptureDevice.Format` / `activeFormat` / `RotationCoordinator`: cannot construct real `AVCaptureDeviceFormat`; any lib doing `device.formats.filter { ... }` then force-unwrapping is at risk. Mitigate by testing against vision-camera in CAM-7 follow-up; fallback is a minimal `AVCaptureDeviceFormat` stand-in (`class_createInstance` subclass overriding `videoSupportedFrameRateRanges`, `formatDescription`, `highResolutionStillImageDimensions`).
- Vision barcode decode unusable on sim; QR only via CIDetector (other symbologies need a bundled decoder).
- Photo via system picker UI untested; use own overlay.
- Swift consumers: `AVCaptureDevice.default(...)` Swift overlays call the same ObjC class methods, so ObjC swizzles apply (expo-camera uses them, confirmed by source reading, not runtime-tested here).
- Private-selector stubbing path is OS-fragile; avoid.
- Photo/metadata/movie delegate callbacks must be dispatched on the output's queue (metadata/video) or main (photo), real behavior.
- Prefer shadow-session also for `AVCaptureMultiCamSession`: not covered.
- Environment note: bare `warden claim` leases time out at 5 min without heartbeats; simctl-driven work does not heartbeat, the sim was shut down mid-spike once (reclaimed on another udid).
