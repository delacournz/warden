# WDN-PERF Wave 2: wall-time and cold-boot work from the e2e audit

> Status: implemented and unit-verified in a Linux container (no simulator or emulator); the device checklist is open. Stacked on `claude/wdn-perf-wave1` (PR #32); finding ids refer to the audit report in PR #31 (`docs/audit/wdn-perf-audit-2026-10-16.md`, raw files `docs/audit/raw/<nn>-*.md`).

## Context

Wave 1 landed the correctness and flake fixes. Wave 2 takes the wall-time and cold-boot items that can be built and unit-tested against the fake drivers and fake exec, and leaves the timing to the device checklist: the Android quick-boot snapshot (on by default, per the interview), the iOS claim path, the headless hide, the `warden e2e` pipeline barriers, launch waits, the fingerprint memo and build-cache pruning, bench fidelity, the tap hit-test, binary size, and `warden ui` state hygiene. Swift (`warden-simd`) and Java (`warden-uiad`) halves of the audit's items wait for a toolchain run and are listed under "Not in this wave".

Decisions applied (interview, report section 9): Android snapshot on by default with `android.snapshot: false` / `WARDEN_ANDROID_SNAPSHOT=0` opt-out; `typescript` resolved from the analysed project; build cache pruned from `warden gc` at 20 GB; contracts additive only; bench runs from a user shell.

## Review

Each merged cluster was read by an adversarial reviewer (one per cluster) that traced findings from a real caller or input to a failure. Their blocking and should-fix findings went to a fix round in fresh worktrees, where each finding had to reproduce as a failing test before any code changed; findings that did not reproduce are marked refuted in the fix reports. Device-only assumptions were collected into the checklist below rather than coded around.

## Device checklist

Run on a Mac with Xcode and an Android emulator before this PR leaves draft (after the Wave 1 checklist in PR #32).

- [ ] android-golden: cold boot time with and without the snapshot on the 16 KB image (`sdk_gphone16k_arm64`); the snapshot loads at all there; `snapshot save` works on a writable instance; `snapshot.pb` marks a finished save; the failed-load log pattern; disk per AVD; `adb reverse` and clock after a load; behaviour after an emulator update; the `emulator` launcher keeps its pid (the liveness watcher relies on it); `-no-metrics`/`-no-audio` on the installed emulator version
- [ ] ios-claim-path: `warden claim ios --count 3` on an empty pool before/after; a fresh clone has `AutomationEnabled` and the driver open shows no `defaults write`; `bootstatus -b` alone on a shut-down sim and what it does on a `Shutting Down` one; `xcode-select` + `version.plist` equals `xcodebuild -version`'s build; a probe under real load is re-probed, a 24 h-old claim quarantine is lifted
- [ ] headless-hide: two `warden e2e --headless` runs at once keep the user's `DetachOnWindowClose`; three sims reboot in parallel; `simctl boot` on an already-booted sim prints `current state: Booted`
- [ ] batch-pipeline: two legs with one slow sim, leg B's first job starts before leg A's warm-up or slim ends; time from the claim's ✔ to the first test before/after; slim spawn count 2 + 36 + loaded labels and no disturbance of the install; `adb kill-server` mid-claim recovers or drops the device; a hung `simctl launch` warns at 30 s; Ctrl-C during the bundle build exits promptly
- [ ] launch-wait: K15 per-rep settle before/after on both platforms; `am start -W` `TotalTime` and the held-first-frame case; a running app opened without relaunch comes to the front as one instance; a permission prompt on API 33+ answered with Allow, and denied on a de-DE device; API 31+ splash ids in the dump
- [ ] fingerprint-memo: `warden app ensure` twice on an unchanged tree spawns no fingerprint the second time; a warm iOS ensure runs no `plutil`; a manual `simctl install` of another build changes the container and executable inode; `<App>.app/<App>` exists in an Expo sim build; gc prunes to the cap and keeps a build installed in the last 30 min
- [ ] bench-fidelity: one run on iOS and Android: CPU-seconds per rep plausible against the old `%cpu`; per-group RSS sums to the host total; the lease shows `bench` with a fresh heartbeat; macOS `ps time` format (over 60 min, zombies)
- [ ] tap-hit-test: iOS snapshots per rep (≈ 170) and `elementAtPoint` span count on the bench; how often the AX hit returns a child label; `.not` assertion time with no recent input; axbridge `hitTest` and SpringBoard prompts
- [ ] cli-size: `bun run --cwd apps/cli build` size on darwin-arm64; `warden affected example` with and without `typescript` in the project; `warden version` and `run --help` RSS
- [ ] ui-state-hygiene: `ps -ww -o command=` of a live recorder and helper shows the marks; `warden ui close` after a pid reuse sends no signal; two parallel `warden ui snapshot` calls keep both records; `batch.json` `logDrainMs`

## Not in this wave

Swift: `rebind`/`settle` taking the launch pid (01-1), guest recycle before launch (03-4), `readMs`/`renderMs` on the wire (02-3), recycle age tied to the launch gap (01-3). Java: `connect_error` classifier (04-1), owner-tagged `warden-uiad` (04-6), prefetch and edit-quiet changes (04-4, 04-5). Policy still open: `warden warm`, keep-booted window (16-13), SessionEnd `--shutdown` scope (16-9), `defaultMax` by RAM (16-16).
