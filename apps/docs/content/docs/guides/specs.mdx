`@delacour/warden-e2e` is warden's own mobile test runner. A flow is a `*.e2e.ts` file run by `bun test`; [`warden e2e`](/docs/guides/run-e2e) leases the simulators, installs the build, starts Metro and runs the specs against them. The package drives iOS simulators and Android emulators directly (see [iOS driver helper](/docs/reference/e2e-driver)), so there is no daemon and no other test runner to install.

```bash
bun add -d @delacour/warden-e2e
```

<Callout type="warn">
`@delacour/warden-e2e` is versioned in lock-step with `@delacour/warden`: install the same version of both, and update them together (`warden update`, then bump the dev dependency).
</Callout>

## A spec

```ts title="e2e/todos.e2e.ts"
import { expect, test } from "@delacour/warden-e2e";

test("add a todo", async ({ device, screen }) => {
  await screen.getByTestId("todo-input").fill("Write e2e flows");
  await screen.getByTestId("todo-add").tap();
  await expect(screen.getByTestId("todos-remaining")).toHaveText("2 left");
});
```

`test(title, options?, body)` receives four fixtures: `app`, `device`, `screen` and `platform` (`"ios" | "android"`). Before every test the runner opens the app fresh (`app.open()`), so a test starts on the app's first screen. Everything a fixture does honours the test's deadline: when it passes, the running driver call is aborted and the test fails with a timeout.

| Option | Effect |
|---|---|
| `timeout` | ms for the whole test, hooks included (default 2 min, `spec.timeout`) |
| `skip`, `only` | skip the test, or run only this one. A leftover `only` fails the run under `CI` |
| `platforms` | run only on these platforms, e.g. `["ios"]` |
| `retry` | extra attempts after a failure; only the last attempt is reported |

`test.skip`, `test.only`, `test.skipIf(condition)` and `test.todo(title)` work as in `bun:test`.

### describe, hooks and settings

```ts title="e2e/settings.e2e.ts"
import { beforeEach, describe, expect, test } from "@delacour/warden-e2e";

describe("settings", () => {
  test.use({ assertionTimeout: 10_000 });

  beforeEach(async ({ screen }) => {
    await screen.getByTestId("tab-settings").tap();
  });

  test("shows the account", async ({ screen }) => {
    await expect(screen.getByTestId("settings-email")).toHaveText("ada@example.com");
  });
});
```

- `describe(title, body)` groups tests; the group title is part of every test title.
- `beforeEach` / `afterEach` hooks receive the same fixtures as a test. `beforeAll` / `afterAll` run once per file or `describe` and receive the base fixtures (`app`, `device`, `screen`, `platform`) but not the ones added by `test.extend`.
- `test.use({ timeout, actionTimeout, assertionTimeout, launch, systemAlerts })` applies to every test in the current file or `describe`. `launch: "none"` skips the fresh `app.open()` before each test.
- `actionTimeout` (default 30 s) bounds each tap, fill and wait for an element; `assertionTimeout` (default 5 s) bounds each `expect(locator)`.
- `systemAlerts: "accept" | "dismiss" | "off"` (default `"off"`) answers an alert that is in the way. With `"accept"` or `"dismiss"`, a locator read, action or `expect` that sees an alert on top answers it (`device.alert("accept")` or `"dismiss"`) and looks again on a fresh screen, three answers at most per look. It answers every alert, the app's own as well as the system's, so leave it `"off"` for a test that asserts on an alert. iOS's "Open in …?" sheet is the exception: `"dismiss"` answers it with Open (Cancel would only throw away a link the test opened), and while `device.openLink` is waiting on a link no read answers any alert, because `openLink` answers the sheet itself.

### Your own fixtures

`test.extend` adds fixtures. A fixture sets up, calls `use(value)` and cleans up afterwards, even when the test failed:

```ts title="e2e/helpers/test.ts"
import { test as base } from "@delacour/warden-e2e";

export const test = base.extend<{ email: string }>({
  email: async (_fixtures, use) => {
    await use(`user-${Date.now()}@example.com`);
  },
});
```

## screen: queries

`screen.getBy…` returns a lazy `Locator`. Nothing is read until you act on it or assert on it, so a locator can be created before the element exists.

| Query | Matches |
|---|---|
| `getByTestId(id)` | the `testID` of the view |
| `getByText(text, { exact?, visible? })` | the visible text (innermost match) |
| `getByLabel(text)` / `getByPlaceholder(text)` / `getByValue(text)` | accessibility label, field placeholder, field value |
| `getByRole(role, name?, { checked?, disabled?, selected? })` | a role such as `button`, `textbox`, `switch`, with an optional name |
| `locator("id=sign-in-submit role=button")` | the selector grammar of [`warden ui`](/docs/guides/agent-ui#targets-and-selectors) |

A string matches the whole text after whitespace is collapsed; `{ exact: false }` makes it a case-insensitive substring; a `RegExp` is tested as written. Refine a locator with `.filter({ hasText, has })`, `.first()`, `.last()` and `.nth(i)`.

Role queries and `visible: true` drop hidden elements. Actions and reads need exactly one match: none gives `LOCATOR_NOT_FOUND`, several give `LOCATOR_AMBIGUOUS` (narrow the query, or use `.first()`).

Whole-screen gestures live on `screen`: `tapAt({ x, y })`, `swipe({ direction })` or `swipe({ from, to })`, and `scrollUntilVisible(locator, { direction?, maxSwipes? })`.

<Callout>
Specs read the accessibility tree, not the React tree. A `testID` is only exposed when the native view is `accessible`, so mark every view a flow taps or asserts as accessible.
</Callout>

## locator: actions and reads

Actions wait for the element (up to `actionTimeout`) and then act:

| Action | |
|---|---|
| `tap({ position?, until?, retries?, windowMs?, pollMs? })`, `longPress({ durationMs? })` | touch the element's centre, or a point inside it. `until` makes the tap retrying (below) |
| `fill(text)` | replace the field's text (focus with the caret at the end, empty it, type the whole string), then poll until the field holds it on consecutive reads, since the accessibility value lags the keys by 100-200 ms; a mismatch is retried once with a fresh clear and retype, then fails with what the field holds. Emptying is select all on iOS and on Android 13+, then the typed text replaces the selection (no Backspace; on Android with `WARDEN_ANDROID_SETTEXT=1`, a field that holds text is replaced in one `setText` call instead); older Android and the retry press one Backspace per character, and a field that is empty or shows its placeholder gets no keys. Secure fields skip the check |
| `type(text)`, `clear()`, `press("Enter", { modifiers? })` | keyboard input; the field is tapped first unless it already has focus. `clear()` checks the field is empty afterwards (secure fields skip the check) |
| `swipe({ direction })`, `scrollTo()` | scroll the element, or scroll until it is visible |

Reads never wait; they answer from the screen as it is now:

`text()` · `value()` · `count()` · `all()` · `allTexts()` · `isVisible()` · `isHidden()` · `isEnabled()` · `isChecked()` · `boundingBox()` · `waitFor({ state: "visible" | "hidden" | "attached" | "detached", timeout })`

`text()` falls back to the text of the descendants when iOS leaves a container's own label empty (a `Badge`, a `Chip`), so asserting on the container works.

`read()` answers several of those from one look at the screen: `{ visible, text?, value?, checked? }`. Nothing matching gives `{ visible: false }`; `text` and `value` are there when the element has them, `checked` only for a switch or checkbox. It is cheaper than `text()` plus `value()` plus `isChecked()`, which each look at the screen. Like the other reads it fails with `LOCATOR_AMBIGUOUS` for several matches.

### Tap until something shows

A tap can land before the screen is ready to take it. Give `tap` the thing the tap should lead to and it checks, and taps again when that is not there:

```ts
await screen.getByTestId("tab-settings").tap({ until: screen.getByTestId("settings-email") });
await screen.getByTestId("sync").tap({ until: async () => (await screen.getByTestId("sync").read()).text === "Synced" });
```

`until` is a locator (visible) or an async function returning a boolean. After the tap it waits up to `windowMs` (default 4000), checking every `pollMs` (default 250), and taps again when the window passes without the check holding, at most `retries` times (default 2, so three taps in all). The last tap is not waited on: when it did not work either, `tap` returns and the next assertion reports what is missing. A locator `until` is checked on the same look at the screen as the poll, so a check costs one snapshot, and that look is also compared with the screen the tap aimed from: once the screen changed (a spinner, a disabled button, the target gone) the tap landed and is never sent again, however late `until` is, and `tap` returns at the end of the window; a screen that has not changed at all is tapped again from 750 ms on instead of after the whole window. A function `until` always gets the whole window. `retries`, `windowMs` and `pollMs` are `INVALID_ARGUMENT` without `until`. Use it for taps that are known to be lost sometimes (a tab bar still animating in); a plain `tap()` is one tap.

### Fewer snapshots

Every read, action and `expect` looks at the screen. The runner keeps the last look for a moment and reuses it when nothing you did since can have changed the screen: a tap, a key, a launch, a settle, any call it does not know all drop it, and it is dropped when it is older than 150 ms on iOS or 1 s on Android. Only the first look of a read or an `expect` may reuse it (later polls are real looks). Anything that aims at an element does not reuse it as it is: `tap`, `longPress`, `fill`, `type`, `clear`, `press`, `scrollTo` and `boundingBox` take a new snapshot, because a snapshot taken while a screen was still sliding in has the element somewhere else, and the tap would land on its neighbour (the one exception, a plain `tap` on iOS that checks the kept look with a hit-test, is below). The confirmation reads that check a `fill` took are real as well, and so are `device.snapshot()` and `device.screenshot()`. So `isVisible()` then `text()` then `expect(...)` is one snapshot, and `expect(a).toBeVisible()` followed by `a.tap()` is two. On iOS, where a hit-test costs a fraction of a snapshot, a plain `tap()` within 150 ms of the look that saw its element, with no input since, takes no second snapshot: it hit-tests its tap point and taps when the hit is the same element in the same place (same role, identifier, label, enabled state and frame), and otherwise looks again as usual. A `tap({ until })` and a test with `systemAlerts` set always take the fresh look. Changes the runner cannot see (the app's own timers, `devtools.evaluate`) show up within that age at most.

## expect: the nine matchers

`expect(locator)` polls every 100 ms for the first second, then every 250 ms, until the check holds or `assertionTimeout` (default 5 s) runs out. Pass `{ timeout }` to override one check.

| Matcher | Holds when |
|---|---|
| `toBeVisible()` / `toBeHidden()` | the element is on screen / absent or off screen |
| `toHaveText(text, { exact? })` | the text equals `text` (a `RegExp` is tested as written) |
| `toContainText(text)` | the text contains `text` |
| `toHaveValue(text)` | the field's value equals `text` |
| `toBeChecked({ checked? })` | a switch or checkbox is on (`{ checked: false }`: off) |
| `toHaveCount(n)` | exactly `n` elements match |
| `toBeEnabled()` / `toBeDisabled()` | the element accepts / refuses input |

`.not` inverts any matcher: `await expect(row).not.toBeVisible()`. A negated matcher passes once its condition has held for 1 s without a break (or the whole timeout, if shorter). Where the driver can tell the app went quiet (iOS with the accessibility bridge, Android with `warden-uiad`), it asks once after the first poll that holds, provided nothing was tapped, typed or pressed in the last second; if the screen is quiet (250 ms without activity), one more fresh look that still holds passes, usually within about 300 ms. Right after an input the full second is held: an app waiting on the network is quiet until the reply comes, so `submit.tap()` then `expect(error).not.toBeVisible()` still sees an error that arrives within that second (a slower reply needs an explicit wait either way). A screen that is quiet but about to change by itself long after the last input (a toast on a timer) can pass before the change; wait for that change explicitly. `expect.soft(locator)` records a failure and carries on; the test fails at the end if any soft check failed. For anything that is not a locator, `expect` is bun's own `expect`.

## app and device

`app` is the app under test (`spec.bundleId`):

`open({ url?, args?, env?, wait? })` · `close()` · `restart()` · `reinstall()` · `clearData()` · `isRunning()`

`open` always starts the app fresh: it terminates a running instance first (iOS: `simctl launch --terminate-running-process`; Android: `am start -W -S` on the launcher activity, which also waits for the first frame, or `am force-stop` then `monkey` when the launcher cannot be resolved), so a device an aborted run left mid-flow does not leak into the next test. It launches with the suite's launch arguments (`--initialUrl <metro url>` for a dev client) plus `args`. `wait: "none"` (the default) returns when the launch call does, before the app is on screen. `wait: "quiet"` then also waits for the first screen and for it to stop moving. A launch screen is idle while the app loads, so open reads the screen after 100 ms, 200 ms, then every 400 ms (fewer full reads while the app starts) until it shows content (a visible control, or any element with a testID; a storyboard or splash has neither), for at most 3 s, then settles (`device.settle()` with 250 ms of quiet, at most 3 s). It is best effort: a first screen with no control and no testID waits out the 3 s, an app that is not quiet in time is returned as it is, and a driver that cannot settle skips the settle. `wait: { until: locator, timeout? }` waits for that locator to be visible (a `TIMEOUT` after `timeout`, default the assertion timeout, like `toBeVisible()`), then settles once, so the next tap lands on a mounted screen; it replaces `open()` followed by `toBeVisible()`: `await app.open({ wait: { until: screen.getByTestId("welcome.screen") } })`. `restart()` is the same relaunch (one stop, not two); `close()` only stops. `launch: "none"` skips the runner's own `open()` and leaves the app as it is. `clearData` wipes the app's data and the keychain; `reinstall` installs the build again from `WARDEN_APP_PATH`.

`device` is the simulator or emulator:

| Call | |
|---|---|
| `alert("accept" \| "dismiss" \| { button })` | answers the system alert on top; resolves `false` when there is none |
| `openLink(url, { accept?, until?, waitMs? })` | opens a URL from outside the app; on iOS answers the "Open in …?" sheet and returns once the link is handled (below) |
| `home()`, `back()` | home button; Android back key (`INVALID_ARGUMENT` on iOS) |
| `orientation(set?)`, `appearance(set?)` | read or set the orientation and the light/dark appearance |
| `clipboard()`, `setClipboard(text)` | the device pasteboard (iOS only; Android throws `E_UNSUPPORTED`) |
| `hideKeyboard()` | dismiss the soft keyboard when it shows (iOS presses Enter, which may submit the field; Android presses back) |
| `screenshot(name)` | saves `screenshots/NNN-name.png` in the test's artifact directory |
| `snapshot({ interactiveOnly? })` | the accessibility tree as text, the text format `warden ui snapshot` prints |
| `settle({ quietMs?, timeout? })` | waits for a quiet UI; resolves `{ quiet, waitedMs, via?, reason?, frontmostPid? }`: `via` is `stream` (the app's run loop went idle), `snapshot` (the helper compared screens instead) or `hash` (warden polled snapshot hashes; on Android one dump that waited out the idle second reports `snapshot`); `reason` explains a not-quiet end (`frontmost_mismatch`: the launched app never came to the front) |
| `devtools` | dev client only, `undefined` in a release build: `evaluate(expr)`, `reloadJs()`, `tree()`, `network`, `console.lines()` / `clear()` / `mark(label)`, `connect()` for the whole facet. The first access attaches |

`openLink` does not wait out a fixed window. It reads the system alert every 100 ms for the first second and every 250 ms after, presses "Open" once the sheet has been up for half a second, since a sheet that is still animating in ignores touches (again if it stays up, three times at most, 600 ms apart) and returns once the sheet is gone. With no sheet it returns after about 1.2 s, as soon as the app is in front: a link that shows no sheet costs about 1.4 s, and later links with the same scheme in the same run return as soon as the app is in front, without reading alerts. While another app (SpringBoard, Safari) is in front it keeps looking for the sheet until `waitMs` (default 8000, the longest wait), then returns without an error. `until` takes a locator and returns as soon as it is visible and no sheet is up, which is the fastest way to wait for the screen the link leads to:

```ts
await device.openLink("myapp://todo/42", { until: screen.getByTestId("todo-detail") });
```

`until` is for a screen the app is not already showing; if `waitMs` passes first, the next assertion reports the missing screen. Android has no sheet, so `openLink` returns at once unless `until` is given. `accept: false` skips the sheet.

`alert()` asks the system for an alert once and returns `false` straight away when there is none. When a sheet is up but its buttons are not readable yet it looks again a few times, 200 ms apart.

## Imports and errors

`@delacour/warden-e2e` exports `test`, `describe`, `beforeAll`, `beforeEach`, `afterEach`, `afterAll`, `expect`, `E2eError`, `WARDEN_E2E_VERSION` and the types `App`, `OpenOptions`, `Device`, `Screen`, `Locator`, `LocatorReading`, `TapOptions`, `TapUntil`, `SystemAlerts` and `TestFixtures`. Everything else is internal.

Every failure a spec sees is an `E2eError` (`instanceof` works) with a `code`: `LOCATOR_NOT_FOUND`, `LOCATOR_AMBIGUOUS`, `INVALID_LOCATOR`, `ACTION_FAILED`, `NOT_ACTIONABLE`, `TIMEOUT`, `INVALID_ARGUMENT`, `ASSERTION`, `SESSION` or `DRIVER`. A locator failure carries the screen as text (`screen`); an ambiguous one the number of `matches`. `WARDEN_E2E_VERSION` is the package version: `warden e2e` refuses to run a spec process whose `@delacour/warden-e2e` version differs from warden's.

## Failure artifacts

When a test fails, the runner writes its evidence next to the results:

```text
<out>/<flow>/<test-title>-<hash>/
  failure.png            the device at the moment of failure
  screen-at-failure.txt  the full accessibility tree, with testIDs, labels and values
  trace.jsonl            every step and every device / driver / locator-read call (`span` lines), with timings
  console.jsonl          dev client: JS console
  network.jsonl          dev client: network requests
  screenshots/           device.screenshot() images
```

Read `screen-at-failure.txt` first: a query that found nothing is almost always an element that is missing or not `accessible` there. Under `warden e2e`, `<out>` is `<batchDir>/e2e/<worker>-<seq>/` and every test also appends one line to `results.jsonl` there; see [Run e2e](/docs/guides/run-e2e#where-to-look-when-it-fails).

## Run a spec by hand

Under `warden e2e` the environment is set for you. By hand, install the build on a simulator you have claimed, then point the spec at it:

```bash
warden claim ios --json                                     # -> udid
WARDEN_UDID=<udid> WARDEN_BUNDLE_ID=com.example.app \
  bun test --preload @delacour/warden-e2e/preload e2e/todos.e2e.ts
```

`WARDEN_UDID` switches the runner on: without it the preload does nothing. Add `WARDEN_PLATFORM=android` for an emulator, `WARDEN_METRO_URL` or `WARDEN_LAUNCH_ARGS` (a JSON array) for a dev client, and `WARDEN_E2E_DEBUG=1` to log every helper call with its duration. The full list is in [environment variables](/docs/reference/environment#set-for-spec-processes). Release the device with `warden release <leaseId>` when you are done.

Without `--preload`, `bun test` fails with `no driver factory configured`. To drop it, add `preload = ["@delacour/warden-e2e/preload"]` under `[test]` in `bunfig.toml`; `warden e2e` passes the preload itself.
