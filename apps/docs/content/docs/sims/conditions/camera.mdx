`warden ui camera set qr-hello.png` swaps a QR image into the example app's camera preview on a leased simulator, then `warden ui wait text "hello"` sees the app's own scanner read it.

[`warden ui`](/docs/sims/ui) feeds a file into the app's real camera API, so the app's own preview, photo capture, video recording and QR scanning run against a known picture. There is no app-side bypass. Simulators and emulators only: a physical device fails with `E_UNSUPPORTED`.

```bash
warden ui camera set fixtures/qr-hello.png            # back camera
warden ui camera set clip.mp4 --facing both --no-loop
warden ui camera status
warden ui camera clear
```

The feed is recorded on your lease and undone on release. With `--json` the answer is `result.camera`. From a spec or a suite: [Camera in E2E tests](/docs/e2e/conditions/camera).

Accepted files: png, jpg, heic (image), mp4, mov (video). warden reads the leading bytes, not the extension. Anything else is `E_CAMERA_MEDIA`, and a missing file is `E_CAMERA_NOT_FOUND`.

## iOS

The app is launched with warden's injected library, which serves the feeds through the real AVFoundation and UIKit API: device discovery, the preview layer, photo output, movie recording, video data output, QR metadata output and the image picker's camera.

- A feed set while the app runs swaps live. Set before launch, it applies on the next launch (`appliesOnLaunch`).
- QR is the only code type decoded.
- Camera permission stays real. `simctl privacy` has no camera service, so the app's prompt shows.

## Android

The emulator's cameras read files fixed at boot, so only a `--camera` emulator can be fed: `warden claim android --camera`, `warden dev android --camera`, or a suite with `camera`. These emulators have their own profile (`<profile>+cam`) and cold boot. They cannot be combined with `--biometrics` yet. Feeding any other emulator fails with `E_CAMERA_DEVICE`.

- An image shows on the app's next camera open (`appliesOnCameraOpen`). An open camera keeps its frames, so close and reopen it (or flip facing).
- A video feed, or switching between image and video, reboots the emulator (`rebooted`).
- Grant the camera permission up front (`warden ui permission set camera=granted`).
- Frame the subject for the preview, not the file. The emulator fills the app's preview from the image and crops the rest, so a code near an edge can fall outside it, and a scanner only reads what reaches the app. With expo-camera on a Pixel emulator, a landscape preview shows about the left half of a 4:3 image: keep a QR code there, with a white margin. iOS passes the whole frame.

Errors and fixes are in [Debugging](/docs/e2e/debugging).
