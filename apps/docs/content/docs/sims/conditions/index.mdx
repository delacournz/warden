An agent (or you) can put a leased device into a condition (offline, 3G, one host failing, a moving GPS fix, a clock two weeks ahead, a failed Face ID, a denied permission, a QR code in front of the camera) and watch what the app does. Everything you change belongs to your lease: when it is released or reclaimed, warden puts it back, so the next agent never inherits a shaped device.

```bash
warden ui network set offline
warden ui location scenario city-run
warden ui clock advance 15d
warden ui permission set location=denied
```

See [warden ui](/docs/sims/ui) for every flag. To keep a condition as a test, set it from a spec or as a suite's starting state: [Device conditions in E2E tests](/docs/e2e/conditions).

The example app has a Conditions screen (`warden-example://conditions`).

## Platform support

Simulators and emulators only: every condition fails `E_UNSUPPORTED` on a physical device.

| Condition | iOS simulator | Android emulator |
|---|---|---|
| [Network](/docs/sims/conditions/network) | the app's `NSURLSession` traffic, through a per-app proxy | native speed and offline; loss and faults through the system proxy |
| [Location](/docs/sims/conditions/location) | points and routes; a route plays once | points and routes, looped or not; the last fix stays |
| [Clock](/docs/sims/conditions/clock) | the app's clock; can be frozen | the emulator's clock; cannot be frozen |
| [Biometrics](/docs/sims/conditions/biometrics) | Face ID and Touch ID | fingerprint |
| [Permissions](/docs/sims/conditions/permissions) | every name but `camera` and `notifications` | the names the manifest declares |
| [Camera](/docs/sims/conditions/camera) | image or video, swapped live; QR decoded | a `--camera` emulator; a video feed reboots it |
| [Locale and timezone](/docs/sims/conditions/locale) | the next launch | live; locale needs Android 13+ |
| [Accessibility settings](/docs/sims/conditions/accessibility) | text size, bold, contrast, reduce motion; a simulated screen reader | text size, bold, reduce motion; real TalkBack |
| [Battery](/docs/sims/conditions/battery) | status bar only | what the app reads |
| [Keyboard](/docs/sims/conditions/keyboard) | live, in an app launched by warden | live, device-wide |
| [Push and memory warnings](/docs/sims/conditions/events) | push | memory warning |

On iOS, network and clock reach only an app launched with warden's network dylib: pass `--relaunch`, or in a suite declare them in `conditions` ([how it reaches the app](/docs/sims/conditions/network#how-it-reaches-the-app)).

## In a spec or a suite

The same conditions are available from a spec (`device.network.set("3g")`), and as a suite's starting state (the `conditions` key in `warden.config.ts`). See [Device conditions in E2E tests](/docs/e2e/conditions), the [suite baseline](/docs/e2e/conditions#suite-baseline-the-conditions-key) and the [timeline](/docs/e2e/conditions#timeline).

## What is undone on release

Release, gc and the end of a spec put the device back:

- network online, faults cleared, the shaping proxy, the flap scheduler and the route ticker stopped
- the location cleared on iOS (Android keeps the last GPS fix: the emulator cannot unset one)
- the clock real again; a still-running injected iOS app is reset to online and the real clock
- permissions reset, text size and contrast or font scale and bold back to defaults, the app locale cleared, the timezone back, the battery real, the keyboard back to `software`, the camera feed off

In a spec, the end of the test puts them back too, and each change is a `condition` line in `results.jsonl`.
