`warden ui network` shapes what the app's own requests see: offline, a preset speed, a flapping link or one host that fails. The rest of the Mac's traffic is untouched, and the network is back online when the lease ends.

```bash
warden ui network set 3g
warden ui network flap --up 10s --down 3s
warden ui network fault api.example.com reset
warden ui network status
warden ui network reset
```

`warden ui network log` is the request log of the dev client. See [warden ui](/docs/sims/ui) for every flag, including `--relaunch`. From a spec or a suite: [Network in E2E tests](/docs/e2e/conditions/network).

## Presets

`set` takes `online`, `offline` or a preset.

| Preset | Latency | Jitter | Down | Up | Loss |
|---|---|---|---|---|---|
| `edge` | 400 ms | 25 ms | 240 kbps | 200 kbps | 0 |
| `3g` | 100 ms | 10 ms | 780 kbps | 330 kbps | 0 |
| `4g` | 170 ms | 15 ms | 9 Mbps | 9 Mbps | 0 |
| `lte` | 50 ms | 5 ms | 50 Mbps | 10 Mbps | 0 |
| `wifi` | 2 ms | 0 | 40 Mbps | 33 Mbps | 0 |
| `slow` | 2000 ms | 100 ms | 400 kbps | 400 kbps | 0 |
| `lossy` | 500 ms | 50 ms | 1 Mbps | 1 Mbps | 10% |

A fault applies to every request whose host matches a glob. Actions: `status:503`, `reset`, `delay:2s`, `blackhole`; `warden ui network fault --clear` removes every fault. A flap and faults do not combine: `network reset` or `fault --clear` first.

## How it reaches the app

| | iOS simulator | Android emulator |
|---|---|---|
| Speed, delay, offline | per-app proxy (a dylib routes the app's `NSURLSession` traffic through the lease's shaping proxy) and a reachability signal | native: `adb emu network`, airplane mode |
| Loss, faults | the proxy | the proxy, through the system `http_proxy` |

A simulator shares the Mac's network, so on iOS a condition reaches only an app that was launched with warden's network dylib. A running app without it fails `E_NETWORK_RELAUNCH`: pass `--relaunch`, or in a suite declare `conditions.network` so every launch carries the dylib.

The shaping proxy binds loopback, and only while it shapes traffic.

## Limitations

- iOS shapes the app's `NSURLSession` traffic only. Raw sockets, `NWConnection` and `CFStream` bypass the proxy.
- Android loss and faults go through the system `http_proxy`: an app that ignores it (a raw socket, `Proxy.NO_PROXY`) is not covered. Speed, delay and offline are native and reach everything.
- A `status` fault cannot answer an HTTPS request (it is reset): HTTPS is tunnelled without being opened.
- Shaping applies to new traffic through the proxy, and an open connection keeps its cost.
