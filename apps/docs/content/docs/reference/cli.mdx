## Quick reference

| Need | Command |
|------|---------|
| one sim / emulator | `warden claim ios --json` · `warden claim android --json` |
| N devices + ports for a script | `warden run ios --count N --port 8091:20 -- <cmd>` |
| One job per device, queued | `warden batch ios --count N --jobs-from jobs.txt -- <cmd {job} {udid}>` |
| a saved batch from `warden.config.ts` | `warden batch <preset> [flags] [-- <cmd>]` |
| which e2e flows a change needs | `warden affected [suite] --base main --explain` |
| run them and gate on the required ones | `warden e2e [suite] --base main --count N` |
| a free port | `warden port claim --json` |
| dev build installed on the device | `warden app ensure ios --udid <udid> --json` |
| duplicate a shut-down sim | `warden clone <udid\|name> [--name x]` |
| pre-build the golden image | `warden golden ensure --profile iphone-17` |
| who holds what | `warden ls` |
| every sim / emulator + who leases it | `warden devices` (alias `warden list`) |
| lighten a booted sim (fewer daemons) | `warden sim slim <udid>\|--booted [--dry-run] [--restore]` |
| tidy Simulator.app windows | `warden arrange` |
| look at / drive a leased device | `warden ui snapshot -i --udid <udid>` · `warden ui press @e3 --settle` ([guide](/docs/guides/agent-ui)) |
| is this device free / mine? | `warden check --udid <udid>` (exit 2 = someone else's) |
| keep a long lease alive | `warden heartbeat --mine` |
| reclaim dead leases | `warden gc` |
| sim + runtime disk usage, what can go | `warden sims` · `warden sims prune --dry-run` |
| pick sims to delete (any owner) | `warden sims delete` (`--suggested -y` off a terminal) |
| is the agent loop fast enough? | `warden ui bench [--runs n] [--json]` |
| setup problems | `warden doctor` |
| update warden | `warden update` (`--check` to only look) |

## Devices

### `warden claim [platform]`

Lease iOS sims / Android emulators — reuse, boot or create — booted and ready. `platform` is `ios | android`, asked for when omitted in a terminal.

| Flag | Default | |
|---|---|---|
| `--profile <slug>` | `iphone-17` / first AVD | device profile, e.g. `iphone-17`, `pixel-10` |
| `--runtime <runtime>` | `latest` | `latest`, `iOS-26-5`, `26.5` … |
| `--count <n>` | `1` | how many devices |
| `--max <n>` | cores/4, cap 4 | max warden devices of this profile |
| `--wait <duration>` | | wait this long for a free device, e.g. `10m` |
| `--ttl <duration>` | `30m` (bare `claim` by an agent: `5m`) | lease TTL without heartbeat |
| `--label <label>` | | shown in `warden ls` |
| `--adopt` | | allow allocating foreign (non-warden) devices |
| `--headless` / `--no-headless` | `WARDEN_HEADLESS`, else off | iOS: close the claimed sims' Simulator.app windows instead of tiling them; `--no-headless` overrides config and env. See [Headless e2e](/docs/guides/headless) |

### `warden release [leaseIds...]`

Release leases, selected by id, `--udid <udid...>`, `--mine` or `--session <id>`. `--label <label>` narrows `--mine` to leases with that label (what subagents should use). `--shutdown` also shuts down devices warden created (or the lease owner booted).

### `warden run [platform] -- <cmd...>`

Claim devices, run a command with `WARDEN_UDIDS` set, release on exit. Takes every `claim` flag, plus:

| Flag | |
|---|---|
| `--port <from:span>` | lease a port for the child (`WARDEN_PORT_<i>`); repeatable |
| `--app` | install the project's app on each device first |
| `--project <dir>` | `--app`: project directory (default: cwd) |
| `--bundle-id <id>` | `--app`: override the bundle id / package |
| `--no-eas` / `--no-build` | `--app`: skip EAS downloads / local builds |
| `--install-mode <clean\|reinstall>` | `--app`: `clean` = fresh app data each run without reinstalling an unchanged build (falls back to reinstall if the reset fails); `reinstall` = uninstall + install each run. Default: install only when the build differs |
| `--reset-keychain` | `--install-mode`: also reset the iOS simulator's keychain (not cleared by uninstall either) |
| `--clean` | deprecated alias of `--install-mode reinstall` |

See [e2e scripts](/docs/guides/e2e).

### `warden batch [platform|preset] [-- <cmd...>]`

Claim devices and fan a job queue out over them, one worker per device; the command runs once per job with `{job}`, `{udid}`, `{worker}`, `{seq}` and `{port}` (the first leased port) substituted. Takes every `run` flag, plus:

| Flag | |
|---|---|
| `--jobs <list>` / `--jobs-from <file\|->` | the jobs: comma-separated, or one per line |
| `--retry <n>` | re-run a failed job up to N times on the same device |
| `--passes <n>` | a job passes only after N consecutive green runs on its device (`WARDEN_PASS`) |
| `--serve <sh-cmd>` | a long-lived process (e.g. Metro) started before the jobs, killed at the end |
| `--serve-ready <probe>` | wait for `http://…`, `tcp:PORT` or `file:PATH` first; `{port}` works here and in `--serve` (`tcp:{port}`) |
| `--serve-timeout <duration>` | give up waiting for `--serve-ready` (default `10m`) |
| `--job-timeout <duration>` | a job still running after this is screenshotted, killed and failed (exit 124); off by default |
| `--record <dir>` | iOS: record every simulator and the TUI (`batch.json`, `tui.cast`, `dev-<i>.mp4`) |
| `--logs <dir>` | per-job logs |
| `--no-tui` | plain log lines instead of the live grid |

With `--headless` (or the preset's `headless`), the leased sims' windows are closed at claim and again before the first job, serve and jobs get `WARDEN_HEADLESS=1`, and `batch.json` has `"headless": true`. `--label` also labels the port leases (default `warden batch`). With fewer jobs than `--count`, only one device per job is claimed.

Each `batch.json` job entry (one per attempt) may carry `logDrainMs`: how long warden waited, after the job exited, for its log pipes to drain, summed over its `--passes` runs.

If the first operand is the name of a preset in [`warden.config.ts`](/docs/reference/configuration#batches) `batches` (found by walking up from the cwd to the git root), that preset supplies the platform and defaults:

- Flags you actually pass override the preset; commander defaults (`--count 1`, `--retry 0`, `--serve-timeout 10m`…) do not.
- `--jobs` / `--jobs-from` replace the preset's `jobs` / `jobsFrom`.
- `-- <cmd>` replaces the preset's `cmd`; without it the preset's `cmd` runs.
- Relative paths in the preset resolve against the preset's cwd (its `project` root, else the config file's directory); paths passed on the command line resolve against your cwd.
- Serve, jobs and a `jobsFrom.command` run in the preset's cwd.
- The label defaults to the preset name.

```bash
warden batch salient-e2e                # everything from the preset
warden batch salient-e2e --count 2 --jobs qa-login -- bun e2e {job} --device {udid}
```

An operand that is neither `ios`, `android` nor a preset fails with the list of presets.

Exits 0 only when every job passed. See [Batches](/docs/guides/e2e#batches-one-job-per-device).

### `warden affected [suite]`

List the flows of `e2e.<suite>` (optional with one suite) that the changes since `merge-base(--base, HEAD)` need: one id per line.

| Flag | |
|---|---|
| `--base <ref>` | compare against this ref (default: the suite's `base`, `main`) |
| `--platform <platform>` | `ios \| android` (default: the suite's `platform`, else both) |
| `--files <list>` | comma-separated changed files (relative to cwd) instead of git |
| `--required-only` | only `required` flows |
| `--explain` | why each flow was picked, with the import chain |
| `--strict` | exit 3 when a changed file reaches no flow |
| `--json` | selections, reasons, skipped and unreached files |

See [Affected e2e](/docs/guides/affected-e2e).

### `warden e2e [suite]`

Select like `warden affected`, then run the flows like `warden batch` — each flow as a `bun test` spec process (`@delacour/warden-e2e`, configured by the suite's `spec`) — and gate: exit 0 when every required flow passed, 1 otherwise, 130 when interrupted. Takes every `batch` flag except the job flags, the `affected` selection flags, plus:

| Flag | |
|---|---|
| `--dry-run` | select and explain, run nothing |
| `--all` | run every flow of the suite (after `include` / `exclude`), no git diff |
| `--flows <list>` | run exactly these flow ids / globs (comma-separated), no git diff; a list matching nothing fails |
| `--report <file>` | also write `e2e-report.json` here |
| `--devices <legs>` | which `devices` legs run: `default` (the default), `all`, or profile names (comma-separated) |
| `--job-timeout <duration>` | overrides the suite's `jobTimeoutMs` (default 10 min) |
| `--no-shutdown` | keep the devices running after the gate passes (the default locally; under CI they are shut down. Suite `shutdown` sets it, the flag wins) |
| `--no-warm` | skip the iOS driver-helper warm-up (the suite's `warmDrivers: false`) |

The suite's `count`, `profile`, `retry`, `passes`, `app`, `ports`, `env`, `serve`, `serveReady` and `serveTimeout` apply unless the flag is passed; `project` sets the cwd. With [`metro`](/docs/reference/configuration#e2e) warden starts and verifies its own Metro before any flow and stops it last. With `devices`, every picked leg claims its own pool and runs the flows concurrently (`--profile` / `--count` replace the legs with one claim); the report then has one verdict per flow and leg. By default (`isolate: "device"`) one spec process per device runs its share of the flows (round-robin by flow id) and every flow still gets its own verdict; `--retry` reruns only the flows that did not pass, and `--job-timeout` / `jobTimeoutMs` is per flow. With `isolate: "flow"` every flow is its own process. While it runs, the grid (or, with `--no-tui`, one line per finished test, `✓ todos › adds a todo (3.21s)` / `✗ …`) ticks flows and tests off as the spec processes append to their `results.jsonl`. The grid's header bar has one cell per flow (one per job with `isolate: "flow"`): green passed, red failed, cyan running, dim pending; each device row has its own bar of the jobs it ran. With `isolate: "device"` every leased device gets a row, cyan while its spec process works; when the run ends warden reads each process's `results.jsonl` and fills the device's bar with the flows it ran there. Flows run in id order (sorted file path), so `count: 1` is a stable serial run. `headless` (suite, else top-level) closes the leased sims' windows at claim and again before the first flow, unless `--no-headless`; `e2e-report.json` records `"headless"` and `"isolate"`. Nothing affected → exit 0 without claiming. Every failed flow is named at the end with its device, spec log and failure screenshot (also `device`, `log`, `screenshot` and a `tests[]` entry per test on the flow in `e2e-report.json`), then each failing test with the first line of its error and its artifact directory. Before the flows, an iOS suite warms the leased devices' driver helpers (`warmDrivers`, on by default) so the first spec does not pay the cold start. Leases are always released at the end. Under CI (`CI` set to anything but empty, `0` or `false`), or with `shutdown: "always"`, a passed gate shuts down the devices warden created (or booted for the run) before releasing them; locally (`shutdown: "idle"`, the default) they stay booted for the next run and `warden gc` shuts them down once idle. A failed or interrupted run leaves them up to inspect, and a sim that was already running when leased is never touched.

### `warden ls`

List leases: resource, state, owner, repo/worktree, age, heartbeat.

### `warden devices [platform]` (alias `list`)

Every simulator / emulator, booted or not, plus Android AVDs — with warden ownership and leases.

### Device health: `release --bad`, `sim unquarantine`

After booting or reusing an iOS sim, `warden claim` checks that `simctl spawn <udid> launchctl print system` answers within 5 s and that SpringBoard is running. A sim this claim just booted (`bootstatus -b` saw the boot finish) only needs SpringBoard running. A device that fails is quarantined (recorded in the store with a reason starting `claim:`, shut down if warden created it) and the claim picks another one; after 2 retries it fails with a clear error. A probe that times out while the 1-min load average is at or above the core count is asked once more after 5 s, and a second timeout only skips the device for this claim: a busy host is not a hung sim. A claim's quarantine expires after 24 h, so the device gets another chance. A foreign device that fails is skipped, never touched. Android has no probe yet.

- `warden release <leaseId…> --bad [reason]` releases and quarantines the devices by hand (warden devices only). Quarantined devices are never allocated and free their pool slot; a quarantine set by hand does not expire.
- `warden sim unquarantine <udid|serial>` clears it. `warden devices` shows `quarantined` and `slim` next to the warden column.
- A claim that has to build the golden image prints `warden ... prewarm with: warden golden ensure --profile <profile>` first.
- `warden app ensure` no longer trusts its install record alone: on iOS it also compares the installed app's `CFBundleVersion`, executable size and `main.jsbundle` size with the cached build, and reinstalls on a difference.

### `warden sim slim [udid]`

iOS. Switches off the launchd jobs inside a booted simulator that UI flows never need — Siri, Apple Intelligence, Health, News, Mail, Photos analysis, Game Center, Wallet and friends (a conservative denylist; SpringBoard, installd, XCTest, the accessibility tree and the keyboard are never touched). A booted simulator runs 200+ such processes; with several simulators side by side, that is the RAM and CPU a flow suite is starved of.

| Flag | |
|---|---|
| `--booted` | every booted simulator instead of one `<udid>` |
| `--dry-run` | list the jobs, change nothing |
| `--restore` | re-enable them (fully effective on the next boot) |

Each job is `launchctl disable`d inside the simulator (remembered across its reboots) and booted out so it stops now. Idempotent. Siri's `assistantd` and `corespeechd` are deliberately left running: the software keyboard asks them about dictation, and with them down an app that shows the keyboard spins its main thread until XCTest can no longer read it. A simulator slimmed by an older warden gets them re-enabled on the next `slim` or `--restore` (effective after its next boot). The disabled state is not copied by `warden clone`, so slim every device you use. A simulator leased by another session is refused. `slim` and `--restore` record the state per device; a plain `warden claim` re-enables a device left slimmed (jobs already booted out stay down until its next reboot). In an e2e suite, `"slim": true` does this on every leased device before `setup` — see [Affected e2e](/docs/guides/affected-e2e#per-device-setup).

### `warden sims audit | prune | delete`

`audit`, `prune` and `delete` share one listing (`simctl list devices -j`: every platform, unavailable runtimes included) and one set of rules, so they always agree about a sim. The only difference is which sims each one acts on.

**Owner.** `warden` (in warden's store, or named `warden-<profile>-N`), `golden` (`warden-golden-…`), or `foreign` (anything else).

**Blockers.** A sim is `leased` (any lease, live or stale; a stale one shows `run warden gc`), `booted`, or `golden`.

**Reasons** (the same text appears in the audit's VERDICT column and in the delete menu hint):

| Reason | Owner | When |
|--------|-------|------|
| runtime removed | any | the sim's runtime is no longer installed (`isAvailable: false`) |
| warden-named, no warden record | warden | `warden-<profile>-N` that the store has no record of (`orphan`) |
| warden sim unused N | warden | not claimed or booted (the later of the store's `lastUsedAt` and `lastBootedAt`) for `--idle` (default `7d`) |
| over --max-size | warden | with `--max-size 40G`, the least-recently-used unblocked warden sims until all sims fit (`budget`) |
| not booted in N | foreign | last booted more than `--stale` ago (default `30d`). Never-booted sims are left alone. |
| older runtime | foreign | older than the newest runtime installed for the same device type and platform |
| duplicate | foreign | same name and runtime as a more recently booted sim |

Warden sims never get `older runtime` or `duplicate`: warden manages its own pool. Goldens never get a reason; they belong to `warden golden prune`.

| Subcommand | Acts on |
|------------|---------|
| `audit` (the default) | nothing; read-only. VERDICT is `keep (leased\|booted\|golden\|recent)`, `delete: <reasons>` (prune will delete it), or `foreign[: <reasons>]` |
| `prune` | warden sims with a reason and no blockers |
| `delete` | any sim you pick except leased ones and goldens. Unblocked sims with a reason start ticked. |

Sizes are simctl's `dataPathSize` (the device's `data/` dir, nearly all of it), with `du` as a fallback.

**Deleting.** `prune` and `delete` use the same delete path. Each sim is leased to the caller under the store lock, and skipped if anyone holds a lease on it, even a stale one. It is then shut down (if its runtime still exists), `simctl delete`d, forgotten from the store, and released. A racing `warden claim` either wins (the sim is skipped) or waits.

#### `warden sims audit`

Lists every sim with its size, owner, lease, last use and verdict, then every downloaded runtime (`xcrun simctl runtime list`, Xcode 15+). For each runtime it shows the size (7–9 GB each), last use, how many sims use it, and a verdict: `in use`, `unused`, `unused after prune` (only sims prune would delete use it) or `unused (not deletable)`. Runtimes are machine-wide, so warden only reports them; free one with `xcrun simctl runtime delete <identifier>`.

Flags: `--idle`, `--stale`, `--max-size`, `--owner warden|golden|foreign|all` and `--json`. In the JSON, each entry has `blockers`, `reasons` and `verdict`, and runtimes sit under `runtimes` (`null` plus `runtimesError` when simctl can't list them). The audit also says if you'd still be over `--max-size` after pruning.

#### `warden sims prune`

Deletes the sims `audit` marks `delete` (`--idle`, `--max-size`). Use `--dry-run` to preview. Off a terminal it needs `--yes`. It never deletes foreign sims or goldens.

#### `warden sims delete [udids...]` (alias `sims rm`)

Permanently deletes simulators. With no udids it opens a multi-select menu (space toggles, enter submits) of every sim. Suggested sims come first and start ticked; the hint shows their reasons, state, runtime and size. Leased sims and goldens are shown but can't be picked. It lists what will go and asks before deleting unless you pass `-y`.

| Flag | Meaning |
|------|---------|
| `--suggested` | delete every suggestion instead of showing the menu |
| `--stale <duration>` / `--idle <duration>` | rule thresholds (same as `audit`) |
| `--dry-run` | only show what would be deleted, with reasons (works off a terminal) |
| `-y, --yes` | don't ask; required off a terminal (with udids or `--suggested`) |
| `--json` | `{ deleted, failed }`, or `{ dryRun, wouldDelete: [{ id, name, reasons }] }`; exits 1 if any sim was skipped |

### `warden arrange`

macOS only. Lines up the open Simulator.app windows of warden sims in name order (`warden-iphone-17-2` before `-10`), left to right from the top-left of the main screen. Simulator windows can't be resized, so a row wider than the screen overlaps evenly, with every title bar left visible; windows wrap to a second row only if the screen is tall enough. Other simulators are left where they are, and Simulator.app is never launched. Every iOS claim (`claim`, `run`, `batch`, `e2e`) runs this automatically unless it is [headless](/docs/guides/headless); set `WARDEN_ARRANGE=0` to turn that off. Moving windows uses System Events, so your terminal needs Accessibility access (System Settings → Privacy & Security → Accessibility).

### `warden clone <source>`

Duplicate a shut-down iOS simulator (udid or name) into warden's pool. `--name` defaults to the next free `warden-<profile>-N`.

### `warden golden ensure | ls | prune`

Golden iOS images new sims are cloned from. `ensure [--profile] [--runtime]` builds once or reuses; `prune` deletes stale goldens (`--all` every golden, `-y` skips the prompt). See [Golden images](/docs/guides/golden-images).

### `warden check`

Exit 0 if a device (`--udid`) is free or yours, **2** if another owner holds it. `--session <id>` checks against that agent session instead of the caller.

### `warden heartbeat [leaseIds...]`

Refresh heartbeats so leases don't go stale. Same selectors as `release`.

### `warden gc`

Reclaim stale leases and shut down unleased warden devices idle for `--idle` (default `20m`). Never deletes devices — use `warden sims prune` to free sim disk. Then prunes the build cache, least-recently-used first, down to `--max-cache-size` (else `WARDEN_MAX_CACHE_SIZE`, default `20G`); builds used in the last 30 min and builds being fetched or built stay, and the notes list what was pruned. `--quiet` prints nothing (used by background auto-gc).

## Ports

### `warden port claim`

`--from` (8091), `--span` (20), `--count` (1), `--ttl` (30m), `--label`. Prints one port per line. See [Ports](/docs/guides/ports).

### `warden port release [ports...]`

By port, `--lease <id...>` or `--mine`. `--force` releases leases held by someone else.

## Builds

### `warden app fingerprint [platform]`

Print the project's native fingerprint (both platforms by default). `--project`, `--bundle-id`, `--variant`.

### `warden app ensure [platform]`

Install the build matching the fingerprint on a device (`--lease <id>` or `--udid`). `--no-install` only resolves into the cache; `--install-mode clean|reinstall` resets the installed app first (`clean`: fresh data, no reinstall of an unchanged build; `reinstall`: uninstall + install), `--reset-keychain` also resets the iOS sim keychain, `--clean` is a deprecated alias of `--install-mode reinstall`; `--no-eas`, `--no-build`, `--project`, `--bundle-id`, `--variant <name>`. See [App builds](/docs/guides/app-builds).

### `warden dev [platform] [-- <expo start args>]`

The worktree-friendly `expo run:*`. Uses the device of `--udid` / `--lease` / your single lease, else claims one (claim options apply). Ensures the `dev` variant's build (or the project's own when it has no `dev`; `--variant` to pick, which must exist), leases a Metro port (`--port`, default `8081:100`) and runs `bunx expo start --dev-client --port <p>` in the project root.

Metro counts as ready (`--ready-timeout`, default `2m`) only once `/status` on that port is proven to serve **this** project root (the `X-React-Native-Project-Root` header, else the listening process's cwd). Another checkout's Metro on the port fails the command with `port <p> is served by <dir>, not this worktree` instead of being attached to.

Then the dev client is opened on the device: iOS relaunches the app with `--initialUrl <metroUrl>` (no "Open in …?" alert); Android runs `adb reverse` and opens `exp+<slug>://expo-development-client/?url=…` (`--scheme` to override). `--no-open` skips this. `--json` prints one line `{ udid, port, metroUrl, leaseIds }` on stdout once Metro is ready (Metro's own output goes to stderr). The device and port stay leased (heartbeat every 30 s) until Metro exits; Ctrl-C stops Metro and releases what it leased. `--no-eas`, `--no-build`, `--install-mode`, `--reset-keychain`, `--project`, `--bundle-id`. `--headless` closes the claimed sim's window and gives Metro `WARDEN_HEADLESS=1`; dev is headless only with the flag (config `headless` and `WARDEN_HEADLESS` don't apply).

### `warden builds ls | prune | import`

- `prune [--max-size 20G] [--dry-run] [--yes]` — remove least-recently-used builds until the cache fits; build-locked ones stay.
- `import <path.app|path.apk> --hash <h> [--platform] [--project] [--profile] [--bundle-id]` — copy a local build into the cache.

## Drive a device

### `warden ui <subcommand>`

The agent CLI over the e2e driver: read the screen, act on it, wait, record flows. Full guide: [Drive a device](/docs/guides/agent-ui). Every subcommand takes the options below, and every call checks the device lease (exit 2 on a foreign or missing lease).

| Option | Effect |
|---|---|
| `--udid <udid>` · `--serial <serial>` · `--lease <id>` | the device (else `WARDEN_UDID`, a single `WARDEN_UDIDS`, your only device lease) |
| `--claim` | take a device when none is leased, or take over a stale lease; `--platform ios\|android`, `--profile <slug>`, `--runtime <runtime>` pick it |
| `--timeout <ms>` | per-command deadline (default 5000) |
| `--no-record` | keep this step out of a running recording |
| `--force` | drive the device even while a live warden process (`warden e2e`, `batch`, `run`, `dev`) holds your lease on it; without it the call exits 2 (`device_busy`) naming the owner, pid and label. Another owner's live lease still refuses |
| `--json` | one JSON document on stdout: `{ok, command, device, generation?, durationMs, result, warnings?}` or `{ok:false, command, error:{code, message, hint?}}` |

Exit codes: 0 ok · 1 failed or usage · 2 lease · 3 engine unavailable (`engine_unavailable`, `devtools_unavailable`) · 4 stale ref · 130 interrupted.

| Subcommand | Notes |
|---|---|
| `status` | device, your lease, the helper and the recording |
| `open <bundleId\|url>` | `--relaunch`, `--metro <url>`, `--args <args...>`, `--settle [ms]`. Without `--relaunch` an app that is already running is attached to, not restarted: the output says `attached to <id>` and `--json` has `attached: true` |
| `close` | stops this device's helper; `--app [bundleId]` quits the app, `--release` frees the lease |
| `snapshot` | `-i`/`--interactive` interactive only, `--all` no line cap, `--depth <n>`, `--settle [ms]` quiet-screen diff |
| `find <selector...>` | elements matching `id=… label=… text=… role=… value=… editable=… nth=…`, with refs |
| `press <target>` (alias `tap`) · `longpress <target> [ms]` | target = `@eN` \| selector \| `x y`; `--verify`, `--settle [ms]` |
| `fill <target> <text>` · `type <text>` · `key <name>` | `fill`: `--secure`, `--no-verify`; `type`: `--submit` |
| `swipe <dir\|x1 y1 x2 y2>` · `scroll <dir> [amount]` | `swipe --from <target>`; `scroll --until <selector> --in <target> --max <n>` |
| `wait` · `is` · `get` | poll the live screen: `wait <selector>\|absent <selector>\|text "…"\|stable [ms]`, `is <selector> visible\|hittable\|enabled\|checked\|selected\|focused` (exit 0/1), `get <selector> text\|value\|label\|id\|role\|frame\|count` |
| `alert accept\|dismiss\|get` · `home` · `back` · `rotate [o]` · `appearance [light\|dark]` | `back` is Android only. `alert get` with no alert shows an empty button list (exit 0); `alert accept\|dismiss` then fail with `no_alert` (exit 1) |
| `screenshot [path]` · `video start [path]\|stop` | default under `$WARDEN_HOME/ui/<udid>/` |
| `eval <expr>` · `tree` · `logs` · `network` · `reload` | dev client only (`--metro <url>`): `eval --await`; `tree --all --max <n> --screen <name>`; `logs [n]\|start [--bodies]\|stop\|mark <label>\|clear`; `network [n] --include headers,body --id <id>` |
| `record start <name> [--out file]\|stop\|status` · `replay <file>` · `export <file> --to <spec>` | `replay`: `--from <i>`, `--update-snapshots`, `--settle [ms]`; `export`: `--ids <module>`, `--force` |

### `warden ui bench`

`warden ui bench [--runs <n>] [--metro <url>] [--udid|--serial|--lease] [--json]` times the agent-loop primitives on a leased device and compares each with its target. `--runs` (default 20) is the sample count; the slow metrics are capped (cold start 3, settle and driver open 5). Run it on a device nobody else is using: the cold-start sample stops the device's helper first, and the press samples tap the middle of the screen.

| Metric | What is timed | Target (p50) |
|--------|---------------|--------------|
| `helperColdToSnapshot` | helper stopped, then connect (spawn) to the first `snapshot -i` (iOS) | < 1500 ms |
| `snapshotWarm` | `snapshot -i` against the resident helper | iOS p50 < 60 ms, p95 < 120 ms; Android < 800 ms |
| `pressHid` | a tap at the screen centre, HID only | iOS < 30 ms; Android < 120 ms |
| `pressSettle` | tap, then `--settle` (wait for a quiet screen, diff) on a static screen (iOS) | < 600 ms |
| `tree` | `warden ui tree` against the dev client (iOS); `skipped: "devtools_unavailable"` without one | < 250 ms |
| `openDriver` | a second driver client opened on the resident helper socket, as a spec does (iOS) | < 500 ms |

A metric passes up to its target times 1.5 (`ok` in the JSON; a loaded machine shows up as `slow`, past the tolerance as `FAIL`). `--json` prints the usual `warden ui` envelope with `result.metrics` as `{ name: { p50, p95, samples, targetMs?, targetP95Ms?, ok? } }` in milliseconds (or `{ skipped, samples: 0 }`), plus `result.passed`. `warden ui bench` itself exits 0; `bun run smoke:ui-bench` (`scripts/smoke/ui-bench.ts`) claims a device, opens the example app, runs it and exits 1 when anything is over target x1.5.

## Setup

### `warden install`

Install warden to `~/.local/bin` plus hooks for detected agents. `--claude`, `--codex`, `-y/--yes`, `--dry-run`, `--shim` (running from source: link `~/.local/bin/warden` to this checkout).

### `warden skill show | install`

`show [--file <name>]` prints SKILL.md, or one file of the skill folder such as `references/ui.md`. `warden install --claude` stages the embedded skill in `$WARDEN_HOME/skill/warden/` and installs it with the same `skills add` command.

`install --from local|github`, `--project`, `-a/--agent <agent...>`, `--copy`, `-y`, `--dry-run`.

### `warden hook session-end`

The SessionEnd hook entrypoint: shuts down what the session booted and releases its leases. Called by Claude Code / Codex, not by hand. `warden hook pretool` still exists as a silent no-op, so a PreToolUse hook written by an older warden keeps working; `warden install` removes that hook.

### `warden doctor`

Check home, db, device tools, the iOS simulator helper, install method (and its upgrade command), `PATH`, Claude/Codex hooks + skill, rule, and stale leases. `--fetch-helper` first downloads `warden-simd` for this version into `$WARDEN_HOME/simd/<version>/`. See [iOS driver helper](/docs/reference/e2e-driver).

### `warden update`

`--check`, `--release`, `--force`, `--to <path>`. npm / bun installs print their package manager's upgrade command instead. See [Updating](/docs/updating).

### `warden version`

Print the version and build channel (`dev` / `local` / `release`).
