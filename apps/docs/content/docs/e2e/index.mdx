## Or set up manually

An e2e test here is a `*.e2e.ts` file that drives your app on a real simulator and asserts on what is on screen. `@delacour/warden-e2e` is the spec API (`test` and `expect` over `bun test`); `warden e2e` leases the devices, installs your app and runs the specs on all of them at once.

This page goes from nothing to one meaningful spec running on several simulators. You need:

- warden installed ([Installation](/docs/getting-started/installation)).
- An Expo app, on macOS with Xcode and an iOS runtime.

No bun install is needed: `warden e2e` runs the specs with the bun built into warden.

<Steps>
<Step>
### Scaffold

```bash
warden init --bundle-id com.example.app
```

`--bundle-id` is only needed when the app has none yet; it is written to `app.json`. `init` writes `warden.config.ts` and `e2e/smoke.e2e.ts`. Existing files are kept (`--force` overwrites), and an app that already has specs gets no smoke spec. `--dry-run` prints the plan. It also prints the install commands for anything missing, such as `expo-dev-client`.
</Step>
<Step>
### Install the spec package

```bash
bun add -d @delacour/warden-e2e@<warden version>
```

Use the version `warden --version` prints: the spec preload refuses any other.
</Step>
<Step>
### Read the config

```ts title="warden.config.ts"
export default {
	projects: [{ name: "my-app", bundleId: { ios: "com.example.app" } }],
	e2e: {
		"my-app": {
			project: "my-app",
			specsDir: "e2e",
			platform: "ios",
			isolate: "device",
			count: 2,
			app: true,
			// no Expo dev menu, onboarding sheet or floating button over the app
			metro: { launchArgs: ["-EXDevMenuShowsAtLaunch", "NO" /* … */] },
		},
	},
};
```

A suite is a named recipe for one run:

| Key | Meaning |
|---|---|
| `project` | which entry in `projects` to build and install |
| `specsDir` | where the `*.e2e.ts` files live |
| `platform` | `"ios"` here; see [Suites](/docs/e2e/suites) for Android |
| `isolate: "device"` | one `bun test` process per device, specs sharded round-robin |
| `count` | simulators to lease (`--count` overrides; `init` writes 2) |
| `app: true` | install the `simulator` build kind: a Release build without a JS bundle, built once per native fingerprint, with your JS repacked into it |
| `metro` | dev-server options; applies when you run with `--dev` |

Every key is covered in [Suites](/docs/e2e/suites) and [Configuration](/docs/reference/configuration).
</Step>
<Step>
### Add testIDs to your components

Specs read the accessibility tree. A `testID` is only exposed when the native view is `accessible`, so mark every view a spec taps or asserts on.

```tsx title="src/todo-list.tsx"
<TextInput testID="todo-input" accessible value={draft} onChangeText={setDraft} />
<Pressable testID="todo-add" accessible onPress={add}>
	<Text>Add</Text>
</Pressable>
<Text testID="todos-remaining" accessible>{`${remaining} left`}</Text>
```

A missing id is fixed here, not with retries or longer timeouts.
</Step>
<Step>
### Write a spec

`init` leaves `e2e/smoke.e2e.ts`:

```ts title="e2e/smoke.e2e.ts"
import { test } from "@delacour/warden-e2e";

test.use({ launch: "none", systemAlerts: "dismiss" });

test("the app opens", async ({ app }) => {
	await app.open({ wait: "quiet" });
});
```

`launch: "none"` skips the runner's own fresh `app.open()`, so the test opens the app itself. `systemAlerts: "dismiss"` answers a system prompt that appears over the app. Now add a test that does something:

```ts title="e2e/todos.e2e.ts"
import { expect, test } from "@delacour/warden-e2e";

test.use({ launch: "none", systemAlerts: "dismiss" });

test("adding a todo updates the count", async ({ app, screen }) => {
	await app.open({ wait: { until: screen.getByTestId("todo-input") } });

	await screen.getByTestId("todo-input").fill("Write e2e specs");
	await screen.getByTestId("todo-add").tap();

	await expect(screen.getByText("Write e2e specs")).toBeVisible();
	await expect(screen.getByTestId("todos-remaining")).toHaveText("1 left");
});
```

The pieces:

- **Fixtures.** `app` opens and closes the app, `screen` finds elements, `device` controls the simulator.
- **Locators.** `screen.getByTestId(id)` is the stable one. Also `getByText`, `getByLabel`, `getByPlaceholder`, `getByValue` and `getByRole`. A locator is lazy: nothing is read until you act or assert.
- **Actions.** `tap()`, `fill(text)`, `type`, `clear`, `press(key)`, `swipe`, `scrollTo`. Each waits for the element first.
- **Assertions.** `expect(locator)` polls until it holds: `toBeVisible`, `toBeHidden`, `toHaveText`, `toHaveValue`, `toBeChecked`, `toHaveCount`, `toBeEnabled`, `toBeDisabled`; `.not` inverts.
- **Open.** `app.open({ wait: { until: locator } })` returns once the screen you name is mounted, so the first tap lands.

Prefer `getByTestId` over text: a text selector breaks when the copy changes. Full reference: [Write specs](/docs/e2e/specs).
</Step>
<Step>
### Run one spec by hand (optional)

Claim a simulator, install your build on it, and point the spec at it:

```bash
warden claim ios --json                       # -> udid
WARDEN_UDID=<udid> WARDEN_BUNDLE_ID=com.example.app \
  bun test --preload @delacour/warden-e2e/preload e2e/todos.e2e.ts
warden release <leaseId>
```

`WARDEN_UDID` switches the runner on; without it the preload does nothing. Add `WARDEN_METRO_URL` for a dev client. A bare claim lasts 5 minutes. Details: [Write specs](/docs/e2e/specs#run-a-spec-by-hand).
</Step>
<Step>
### Run the suite

```bash
warden e2e              # the suite's own count
warden e2e --count 3    # three simulators
```

With one suite in the config the name is optional. warden leases the simulators, installs the app, starts Metro when you pass `--dev`, and spreads the specs over the devices. The first run of a native fingerprint builds the app (minutes); later runs reuse the cache. A project without `@delacour/warden-e2e` fails before any device is claimed.
</Step>
<Step>
### Read the evidence when it fails

Every run writes a batch directory, `$WARDEN_HOME/batches/<id>` (`WARDEN_HOME` defaults to `~/.warden`).

| File | What it tells you |
|---|---|
| `e2e-report.json` | verdict per spec and per test (`--json` prints it) |
| `e2e/<worker>-<seq>/results.jsonl` | every test's status, duration and error |
| `<spec>/<test>-<hash>/screen-at-failure.txt` | the accessibility tree when the test failed. Read this first: a query that found nothing is an element that is missing or not `accessible` |
| `<spec>/<test>-<hash>/failure.png` | the screen at that moment |
| `<spec>/<test>-<hash>/trace.jsonl` | every step and device call, with timings |

The per-test folder sits under `e2e/<worker>-<seq>/`. Paths, log files and fixes for common failures: [Debugging](/docs/e2e/debugging).
</Step>
</Steps>

## Let your agent write it

You do not have to type specs. Your agent drives the app with [`warden ui`](/docs/sims/ui) between `warden ui record start <name>` and `warden ui record stop`. `stop` writes the spec to `<specsDir>/<name>.e2e.ts`, lints it, merges the testIDs it used into a module, and runs it once on the same device. There is no intermediate file: the spec runner is the replay. Details: [Author specs by recording](/docs/e2e/author-specs).

If your agent does not know warden yet, see [Set up your agent](/docs/getting-started/agent-setup). Then paste:

```text
Use warden to write an e2e spec for adding a todo in this app.
1. Claim a simulator, open the app, and record: warden ui record start add-todo --udid $UDID.
2. Drive the flow with warden ui. Target elements by testID (id=...). If snapshot -i marks an element [no-id], add testID and accessible in the component first.
3. Add one `warden ui record note "<step>"` per user-visible step, and assert the result with warden ui wait.
4. warden ui record stop. If verify fails, read screen-at-failure.txt, fix the app or undo and redo the steps, and stop again.
5. Release the device with warden ui close --release.
```
