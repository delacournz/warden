Use this page to run `warden e2e` on a macOS GitHub Actions runner; it covers installing warden, the run command, headless behavior and cleanup.

```yaml title=".github/workflows/e2e.yml"
jobs:
  e2e:
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: oven-sh/setup-bun@v2
      - run: bun install
      - uses: delacournz/warden/.github/actions/install-warden@main
      - run: warden e2e mobile --base origin/main --count 2 --report e2e-report.json
```

`fetch-depth: 0` gives warden the history it needs for the merge-base against `--base`. The same command runs locally or in a pre-push hook.

## Install warden

Two routes:

- **npm:** `npm i -g @delacour/warden`, or `bunx @delacour/warden`. It is a node shim plus one prebuilt binary per platform (macOS and Linux, `arm64` and `x64`); an install with `--omit=optional` leaves the shim without a binary.
- **Install action:** `delacournz/warden/.github/actions/install-warden` downloads the release binary for the runner (`warden-darwin-arm64` …), checks it against `checksums.txt`, installs it to `~/.local/bin/warden` and puts that on `PATH`. Inputs: `token` (default: the workflow's `github.token`, which can read the public releases), `version` (a tag such as `v0.1.0`; default `latest`) and `repo` (default `delacournz/warden`).

A private fork in `repo` needs a `token` with Contents: read on that repo.

`@delacour/warden-e2e` is a dev dependency of your app at the same version as warden; `bun install` brings it in. A mismatch makes the preload exit 2.

## What the runner needs

- macOS for iOS simulators, with Xcode and the iOS runtime installed; Android needs the SDK. There is no Windows support.
- No bun install: warden runs the specs with the bun built into its own binary, so CI needs no bun install (`WARDEN_BUN` picks a different one).
- No prior state. The `--profile` is created on claim, cloned from a golden image that is built on first use (about four minutes on a hosted runner); keep it between runs with `warden golden export` / `import` and `actions/cache` ([below](#reuse-a-prebuilt-app-and-the-golden)). If cloning fails it falls back to `simctl create`.

## Gate a pull request

`warden e2e <suite> --base origin/main` runs only the specs the diff needs ([Affected](/docs/e2e/affected)). It exits 0 when every required spec passed or nothing was affected (no device claimed), and 1 when a required one failed. Parsed imports are cached under `$WARDEN_HOME/affected`. The compiled `warden` binary carries no TypeScript compiler, so add `typescript` 5.0 or later as a dev dependency of the app.

Keep the evidence when a run fails:

```yaml
      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: warden-e2e
          path: |
            e2e-report.json
            ~/.warden/batches
```

## Reuse a prebuilt app and the golden

On a fresh runner, a `simulator`-kind suite (`app: true`) pays twice before the first spec runs: a native Release build of the simulator base, and the golden image's first boot. When another job already builds the Release simulator `.app`, import it; cache the golden between runs.

```yaml title=".github/workflows/ios.yml"
jobs:
  ios-build:
    runs-on: macos-26
    steps:
      - uses: actions/checkout@v4
      # … install dependencies, pod install …
      - run: |
          xcodebuild -workspace ios/App.xcworkspace -scheme App -configuration Release \
            -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
            ARCHS=arm64 ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO \
            -derivedDataPath ios/build/dd build
      # upload-artifact zips files and drops the executable bit: ship the .app as a tarball
      - run: tar -czf App.app.tgz -C ios/build/dd/Build/Products/Release-iphonesimulator App.app
      - uses: actions/upload-artifact@v4
        with: { name: ios-simulator-app, path: App.app.tgz }

  e2e:
    needs: ios-build
    runs-on: macos-26
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: oven-sh/setup-bun@v2
      - run: bun install
      - uses: delacournz/warden/.github/actions/install-warden@main

      - uses: actions/download-artifact@v4
        with: { name: ios-simulator-app }
      - run: tar -xzf App.app.tgz && warden builds import App.app --kind simulator-base

      - id: golden
        run: echo "name=$(warden golden key --profile iphone-17)" >> "$GITHUB_OUTPUT"
      - id: golden-cache
        uses: actions/cache/restore@v4
        with: { path: ~/warden-goldens, key: "${{ steps.golden.outputs.name }}" }
      - run: warden golden import ~/warden-goldens

      - run: warden e2e mobile --all --count 1

      - if: steps.golden-cache.outputs.cache-hit != 'true'
        run: warden golden export ~/warden-goldens --profile iphone-17
      - if: steps.golden-cache.outputs.cache-hit != 'true'
        uses: actions/cache/save@v4
        with: { path: ~/warden-goldens, key: "${{ steps.golden.outputs.name }}" }
```

**The base.** `warden builds import <App.app> --kind simulator-base` files the `.app` as the base every repack clones, under warden's own native fingerprint of the project (`--project <dir>` when the app is not in the working directory). The next `warden e2e` / `warden repack` bundles this checkout's JS into it in seconds instead of building. The import refuses a `.app` that is not a simulator build, has no slice for this Mac (`arm64` on Apple silicon), has another bundle id (`--bundle-id` overrides), is a Debug or expo-dev-client build, or whose executable lost its mode bits. A `main.jsbundle` embedded by the build (no `SKIP_BUNDLING`) is stripped from the cached copy; every repack writes its own.

The fingerprint is warden's, not `@expo/fingerprint`'s: they differ. To key an artifact or check which base a run will look for, print it with `warden app fingerprint ios --kind simulator --json` (`fingerprints.ios`, and `hashes.ios` = `<fp>:base`). `--hash <fp>` files the import under a fingerprint you computed earlier. A base whose fingerprint no longer matches the checkout is never used: the run builds one, as without an import.

**The golden.** `warden golden key` prints the golden's name, `warden-golden-<profile>-<key>-r<recipe>`, where the key covers the Xcode build, the runtime build, the device type and the recipe: a runner image with another Xcode or runtime gets another cache entry. `warden golden import <dir>` exits 0 whatever it finds: a cache miss, an archive for another Xcode or runtime, or a broken one is skipped with the reason, and the first claim builds the golden as before. Use the same `--profile` (and `--runtime`) as the suite's devices. Keep the export and save steps on the default `success()` condition (not `always()` or `!cancelled()`): a golden saved by a failed run is restored by every later run. `warden golden export` itself refuses a golden that never settled after its first boot. An archive is about 2 GB before compression; GitHub keeps 10 GB of caches per repository. See [Golden images](/docs/sims/golden-images#carry-a-golden-between-machines).

## Run e2e in GitHub Actions

`delacournz/warden/.github/actions/e2e` is a composite action that runs a suite on a macOS runner with every cache and guard this page describes already wired up. Call it after `actions/checkout`:

```yaml title=".github/workflows/e2e.yml"
name: e2e
on:
  pull_request:
    paths: [apps/mobile/**, bun.lock]
  push:
    branches: [main]
    paths: [apps/mobile/**, bun.lock]

permissions:
  contents: read

jobs:
  ios:
    runs-on: macos-26
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v7
        with: { fetch-depth: 0 }
      - uses: delacournz/warden/.github/actions/e2e@v0.12.2
        with:
          working-directory: apps/mobile
          suite: mobile
          count: 1
          retry: 1
          args: --base origin/main
          save-cache: ${{ github.event_name != 'pull_request' }}
```

Pin the action to a commit SHA or release tag. In order, it:

1. Sets `WARDEN_TELEMETRY_DISABLED=1` and `DO_NOT_TRACK=1`, selects `xcode-path` through `DEVELOPER_DIR` when given, and lets `simctl` answer once so the first CoreSimulator call does not land inside a claim's 30 s timeout.
2. Installs bun from npm (`npm i -g bun@<version>`) when none is on `PATH`, so it needs no third-party action; `bun-version` defaults to the root `packageManager`. Runs `install-command` (default `bun install --frozen-lockfile`) with `npm-token` as `NPM_TOKEN`.
3. Installs the release binary of `warden-version` (checksum verified) and runs `warden doctor --fetch-helper`.
4. Restores the three caches below, imports `app-path` when given, then runs `warden e2e` with `--report` and the inputs as flags.
5. On failure prints every `screen-at-failure.txt` into the job log (one `::group::` each) and always uploads the report plus `~/.warden/batches` as an artifact (`retention-days`, default 3).
6. After a green run only, and only when `save-cache` is `true`, saves the caches. Restore and save are separate steps, so a failed run saves nothing.

| Input | Default | Meaning |
|---|---|---|
| `working-directory` | `.` | where `warden.config.ts` lives |
| `suite` | suite's only | `e2e.<suite>` |
| `profile`, `count`, `retry` | the suite's | `--profile`, `--count`, `--retry` |
| `args` | none | extra `warden e2e` flags (`--all`, `--base origin/main`, `--specs a,b`) |
| `app-path` | none | a simulator `.app` built earlier in the workflow, imported as the base |
| `warden-version` | `latest` | release tag, or `none` when warden is already on `PATH` |
| `bun-version` | root `packageManager` | bun to install from npm when none is on `PATH`; `none` skips |
| `install-command` | `bun install --frozen-lockfile` | empty skips; `install-working-directory` picks where it runs |
| `xcode-path` | runner default | e.g. `/Applications/Xcode_27.2.app` |
| `headroom-gb` | 1 on hosts of 16 GB or less | `WARDEN_CAPACITY_HEADROOM_GB` |
| `report-path` | `warden-e2e-report.json` | where the report goes |
| `cache` | `github` | `github` saves and restores with `actions/cache`; `none` leaves storing to you (see below) |
| `cache-prefix` | `warden-e2e-v1` | change it to drop every cache |
| `js-inputs` | `src assets app.config.ts index.ts metro.config.js package.json` | git pathspecs that key the repack cache; mirror `kinds.simulator.jsInputs` |
| `save-cache` | `true` | `false` on pull requests |
| `retention-days`, `artifact-name` | `3`, `warden-e2e` | the evidence artifact |

Outputs: `report-path` (absolute), `passed` (`true` / `false`) and `cache-groups` (the JSON below). The job fails when the gate fails.

### The caches

| Cache | Path | Key | Saved |
|---|---|---|---|
| Native build | `~/.warden/builds` without the repacks | runner + `warden app fingerprint ios --kind simulator --json` (`.fingerprints.ios`) | after a green run on a miss |
| JS repack | `~/.warden/builds/*/ios/*/simulator/repacks` | the fingerprint + a hash of `js-inputs` (`git ls-files -s`) | after a green run on a miss |
| Golden simulator | `~/warden-goldens` | `warden golden key --profile <p>` (Xcode build, runtime build, device type, recipe) | after a green run on a miss |

A native build is minutes of `xcodebuild`, the JS bundle about 3.5 minutes on a hosted runner, and a cold golden up to five more minutes of first boot and settling. A pull request restores what the default branch saved but never saves (`save-cache: false`), so a branch cannot evict the default branch's entries; a push to the default branch fills them. A JS-only change misses only the repack cache. A new Xcode or runtime image misses only the golden. The caches hold files, not `warden.db`: a base or repack dir that comes back complete with no row is registered on its first lookup (`warden builds --json` shows `"source": "restored"`) and used as it is.

### Bring your own cache

With `cache: none` the action never calls `actions/cache`. It still imports the golden from `~/warden-goldens` before the run, but never exports it: a golden your cache already restored would be exported for nothing. When your cache missed it, run the golden's `beforeSave` after a green run, then save the directory. `warden ci cache --json` (the action's `cache-groups` output) lists them, on any CI:

```json
{
  "builds": { "kind": "paths", "key": "warden-e2e-v1-builds-macOS-ARM64-<fp>", "paths": ["/Users/runner/.warden/builds", "!/Users/runner/.warden/builds/*/ios/*/simulator/repacks"] },
  "repack": { "kind": "paths", "key": "warden-e2e-v1-repack-macOS-ARM64-<fp>-<js>", "paths": ["/Users/runner/.warden/builds/*/ios/*/simulator/repacks"] },
  "golden": {
    "kind": "archive",
    "key": "warden-e2e-v1-macOS-ARM64-warden-golden-iphone-17-<key>-r2",
    "paths": ["/Users/runner/warden-goldens"],
    "afterRestore": "warden golden import /Users/runner/warden-goldens",
    "beforeSave": "warden golden export /Users/runner/warden-goldens --allow-unsettled"
  }
}
```

A `paths` group is stored as it is (a `!` path is left out of the one before it). An `archive` group needs its commands around it: `afterRestore` after you restore it, `beforeSave` before you save it. With `cache: none` the action runs `afterRestore` for you; `beforeSave` is yours. Run it from the project (`--project <dir>`), with the same `--prefix`, `--profile` and `--js-input` you pass the action. On a runner with a persistent cache volume (Namespace, a self-hosted Mac), mount the paths and skip the keys:

```yaml
- uses: namespacelabs/nscloud-cache-action@v1
  with:
    path: |
      ~/.warden/builds
      ~/warden-goldens
- uses: delacournz/warden/.github/actions/e2e@<sha>
  with:
    working-directory: apps/mobile
    cache: none
- name: Keep the golden on the volume
  if: success()
  working-directory: apps/mobile
  run: '[ -n "$(ls -A ~/warden-goldens 2>/dev/null)" ] || warden golden export ~/warden-goldens --allow-unsettled'
```

On another CI, key each group by its `key` and restore before `warden e2e`:

```bash
groups=$(warden ci cache --json --project apps/mobile)
# restore every group's paths under its key, then:
warden golden import ~/warden-goldens
warden e2e --project apps/mobile
# after a green run, only when the golden missed: warden golden export ~/warden-goldens --allow-unsettled; then save each group under its key
```

### Reuse an app built earlier in the workflow

Build the `.app` with ad-hoc signing and pass it in. `CODE_SIGNING_ALLOWED=NO` leaves the simulator app without entitlements, and every Keychain call then fails with `errSecMissingEntitlement` (-34018).

```yaml
      - run: |
          xcodebuild -workspace ios/App.xcworkspace -scheme App -configuration Release \
            -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
            ARCHS=arm64 ONLY_ACTIVE_ARCH=YES CODE_SIGN_IDENTITY=- \
            -derivedDataPath ios/build/dd build
      - uses: delacournz/warden/.github/actions/e2e@v0.12.2
        with:
          app-path: ios/build/dd/Build/Products/Release-iphonesimulator/App.app
```

`warden builds import` prints a warning when the `.app` has no `application-identifier` entitlement (`codesign -d --entitlements :- App.app` shows it).

### Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `queued #1 of 1 … mem binds: need 1792 of 0 memory` | a 7 GB hosted runner leaves no budget after warden's 8 GB headroom | the action sets `WARDEN_CAPACITY_HEADROOM_GB=1`; a lone claim is admitted either way |
| ``xcrun simctl list devices … did not finish within 30s`` | the first CoreSimulator call of a cold image, under a native build's load | the action calls it once before the run; keep `count` at 1 on a 3-core runner |
| first spec on each simulator fails, the rest pass | the in-sim bridge is up but silent | `retry: 1`; warm-up retries its snapshot for 120 s and warms one device at a time |
| `errSecMissingEntitlement` / `-34018` in the app | simulator app built with `CODE_SIGNING_ALLOWED=NO` | build with `CODE_SIGN_IDENTITY=-` |
| golden "not settled after 300s" | a loaded 3-core runner | the run still works. With `cache: github` the action exports it with `warden golden export --allow-unsettled`, so the next run restores it instead of building it again. A bigger runner settles it |
| `warden: command not found` | `warden-version: none` without an earlier install | install warden first or leave the default |
| `bun: command not found` after a blocked `setup-bun` | an allowlist blocks third-party actions | the action never uses one: leave `bun-version` empty or pin it |
| cache never hits | the key moved: Xcode image, fingerprint or `js-inputs` changed | read the `Key the caches` step: it prints the fingerprint and golden name |

## Headless and cleanup

Simulators boot without a window. On a CI runner nothing else is open, so no flag is needed; `--headless` guarantees it when Simulator.app is running ([Headless](/docs/sims/headless)). Under `CI`, a passed gate shuts down the simulators and emulators warden created for the run, and a failed run leaves them booted. `--no-shutdown` keeps them up. A leftover `test.only` fails the run under `CI`.
