# @delacour/warden

The `warden` binary. `src/cli.ts` dispatches to `src/commands/<name>.ts` (listed in `commands/registry.ts`); only the dispatched command's module is imported (`runLazyProgram`).

## Patterns
- CLI framework: **commander** via `@commander-js/extra-typings` (typed args + opts, no `any`). Each command is `defineCommand({ name, group, summary, aliases?, register })` in `src/commands/<name>.ts`, listed in `commands/registry.ts` as a `CommandEntry` (same `name`/`group`/`summary`/`aliases`/`hidden` + `load: async () => (await import("./<name>")).<name>Command`); `registry.test.ts` fails when a listing drifts from its module, `help.test.ts` snapshots every `--help` (`bun test -u` after an intended change). `register(cmd, ctx, done)` adds `.argument()`s, `.option()`s and nested `cmd.command(...)` subcommands; every `.action()` calls a plain function `(ctx, args…, opts) → Promise<number>` and reports it with `done(code)`. `xCommand.run(ctx)` parses `ctx.argv` (what tests call); `runProgram` builds a fresh program per run; `runLazyProgram` loads just the dispatched command (root `--help`, no args, `help <cmd>` and unknown commands load them all: commander prints argument placeholders and "did you mean" from the registered set).
- Cold start matters (hooks, the 30 s heartbeat, every agent call): `startup.test.ts` runs the CLI in a child process and asserts which modules `version` / `heartbeat` / `claim` / `gc` / `release` / `ui <sub>` / `batch` load. Don't statically import heavy modules (`agent-ui/close` → the iOS driver + zod, `@delacour/warden-e2e`, `typescript`) from a command that runs on every agent session; import them where the work happens (see `agent-ui/stop-helper-after.ts`, `stopHelperAfter`).
- Usage errors (unknown option, missing/excess args) are commander's: printed in red to `ctx.err`, exit 1; `--help` → exit 0. Validate values (durations, ints, platforms) in the action and `reportError(ctx, "<cmd>", message)` + return 1.
- One look, taken from the `warden batch` grid: bold `warden <cmd>` title + dim detail, cyan accents (spinner, running, help names), green `✓` / red `✗` / yellow `!` / dim `·` (`SYMBOLS` in `ui.ts`). `output.ts` owns it: `heading(ctx, scope, detail)` (or `emit(…, { scope, detail })`) for the title, `reportError` / `warn` / `success` / `note` for status lines, `table(ctx, header, rows, flex?)` for tables (the `flex` column gives way to fit the terminal). Titles and glyphs appear only when `ui.rich` (stdout + stderr are TTYs, not CI) and always on stderr: piped / `--json` / agent output is unchanged plain text, so never print decoration with `ctx.out`. Don't hand-roll `ctx.err(color.red(…))`.
- `warden --help` lists commands under their `group` (`COMMAND_GROUPS` in `command.ts`: Lease, Run, Devices, Builds, Setup); help is styled and wrapped to `ui.columns` in `helpStyle`.
- Shared option sets are typed helpers: `withClaimOptions(cmd)` (claim + run), `withSelectOptions(cmd)` (release + heartbeat). Every command keeps `--json` (stdout = one JSON document, nothing else on stdout).
- UI lives on `ctx.ui` (`ui.ts`; ora and @clack/prompts load on first spinner / prompt, not at start-up): `color` (chalk instance — respects NO_COLOR/FORCE_COLOR/TTY; never import chalk's default instance), `spinner(text)` (ora on stderr; `withSpinner(ctx, text, work)` routes the work's `ctx.err` lines above the spinner), `confirm` / `select` / `multiselect` (@clack/prompts; `undefined` = cancelled → `ui.cancelled("Aborted.")`, exit 1). Only prompt when `ui.interactive` and no `--yes`; otherwise fail with a message naming the flag. Exception: `warden install` treats a cancelled/declined prompt as "skip that step" and carries on. `warden hook` output is machine-read: no colour, spinners or prompts there.
- All I/O through `CommandContext` (`out`/`err`/`store()`/`exec`/`now`/`env`/`ui`) — tests use `testing.ts` `testContext()` (+ `scriptedUi({ interactive, rich, columns, confirm, select, multiselect })`, whose `events` log spinners/prompts) and `fakeExec()`.
- Git facts (toplevel, common dir, branch) are one `git rev-parse` per directory per command: `ctx.git` is that command's `GitFactsCache` (`@delacour/warden-core/git-facts`; a read inside a checkout also answers for its toplevel). `resolveOwner`, `port`, `batch` presets, `affected` and every `projectContext` caller (`project-context.ts` `projectContextFor(ctx, …)`) read through it, so ask it instead of spawning `git rev-parse --show-toplevel` / `--abbrev-ref`; tests pre-fill it with `ctx.git.store(cwd, facts)`.
- `commands/affected-graph.ts` is the hidden `warden __affected-graph '<request json>'` (`GRAPH_WORKER_SUBCOMMAND`, out of `--help`): the import-graph walk of `warden affected`. `graph-process.ts` runs it as `<warden> __affected-graph` when this is a compiled binary (no `graph-worker.ts` on disk; `compiledBinary()` = `Bun.main` under `/$bunfs/`) and as `bun graph-worker.ts` from source, so the TypeScript compiler (~90 MB) never loads in the CLI process; no top-level `await` in `graph-worker.ts` (bytecode bundles as CommonJS).
- Devices come from `providers.ts` `providerFor(platform, ctx, owner)`; claim flags + owner resolution in `claim-flags.ts`; lease selection (`<id…>|--udid|--mine|--session`) in `lease-select.ts`.
- `device-lease.ts`: `ensureCallerLease(store, owner, platform, id, {now, pidAlive, claim, label})` (own → heartbeat · live foreign → `device_foreign` + `blockMessage` · stale/none → taken over only with `claim`, else `device_not_leased`) is the one lease check, used by `warden ui`. `releaseDevices(host, leaseIds, { after?, touch?, only? })` is the single CLI choke point for deleting leases (release, lease-session, SessionEnd, gc): synchronous delete, then the async `after(udid)` teardown per device lease.
- `agent-ui/` + `commands/ui.ts`: `warden ui <sub>` for agents. `ui-options.ts` `withUiOptions` (the "global" flags `--udid --serial --lease --claim --platform --profile --runtime --timeout --no-record --json`, per subcommand because commander keeps parent options positional; kept out of `run.ts` so registering loads no device code) + `run.ts` `runUi` (validate → `resolveUiDevice` in `device.ts` → work → text or one `UiJson` envelope, throws → `failed`). `output.ts`: `UiJson`, `UI_ERROR_EXIT` (code → exit 0/1/2/3/4/130). Add a subcommand = one `cmd.command(...)` in `ui.ts` whose action imports (`await import("../agent-ui/x")`) a function in `agent-ui/*.ts` that uses `runUi` — never a static import, so a call loads only its own module and `ui --help` loads none (`startup.test.ts` "warden ui"); `record`/`replay`/`export` and `eval`/`tree`/`logs`/`network`/`reload` are wired in `flows-register.ts` / `devtools-register.ts` the same way. `createUiCommand(deps: UiDeps)` injects the driver (`ui-driver.ts` `uiDriver`, imported by `defaultUiDeps.driver` on first open — `driver.ts` itself stays light: iOS = the device's `warden-simd` daemon via `connectHelper`, Android = an adb-backed driver owned by the command; `engine_unavailable` only when the helper/adb is missing) + sleep; `runUi` hands work a lazy `env.driver()` and closes it. Screen model on `@delacour/warden-e2e` (`screen/*`, `driver/refs|settle`): `snapshot.ts` (`takeSnapshot`, `findElements`: one generation bump per call, refs numbered over the whole tree), `diff.ts` (`+/-/=` keyed id → role+label → path), `state.ts` (`$WARDEN_HOME/ui/<udid>/{state,last-snapshot}.json`, atomic writes), `helper.ts` (imports the e2e iOS driver / simd client only inside `connectHelper` / the default `connect`, so `status`/`close` read the record without loading a driver; iOS `warden-simd` daemon per device at `$WARDEN_HOME/simd/<udid>.sock`: `ensureHelper`/`connectHelper` — one spawner arbitrated by the `simd_spawn:<udid>` meta row, detached spawn whose stdout pipe is read for the helper's `ready` line (`watchStart`; no ready line = the 100 ms socket poll; waits on anything live — its own starting child, a live row, a busy helper — up to 15 s, and a spawner that gives up SIGTERMs its child; no socket file = spawn at once; a handshake timeout with the recorded pid alive = busy: waited for ≤5 s, then stopped and replaced, never run beside), one connect whose client `keepClient` hands to `openIosDriver({client})`; the record in `state.json` keeps the helper binary (realpath + mtime), a `WARDEN_SIMD_*` env hash (`simdEnvKey`) and the lease it was spawned under, and a resident helper whose binary or env differs is replaced, unless it was spawned under the device's current lease (owner churn alone never replaces it); `stopHelper` — takes the spawn row (≤1 s), `shutdown`, ≤2 s, SIGTERM, then unlinks the socket only if it is the same file and forgets the record only if it names the same pid; `sweepDeadHelpers` for gc, dead pids only: gc calls `helper-sweep.ts` `sweepDeadHelpersLazily`, which reads the `state.json` records as plain JSON and imports `helper.ts` only when a recorded pid is dead, so a gc with live or no helpers never loads the e2e driver or zod; `startup.test.ts` guards gc/release; `paths.ts` holds `uiDir`/`simdDir` so light modules need not import `state.ts`). Helpers stay resident after a release (idle exit, `$WARDEN_SIMD_IDLE_TIMEOUT`, 10 min): `stop-helper-after.ts` `stopHelperAfter` is the `after` hook only where a helper must go with the lease (`release --shutdown`, `ui close --release`, gc of a stale lease, `shutdownReleasedDevices`, gc's idle shutdown); it imports `helper.ts` lazily so release/gc/hook never load the e2e driver, `target.ts` (`@eN` | selector | `x y`; refs older than 30 s or `--verify` re-checked → `stale_ref`). `query.ts` (`find`/`get`/`is`/`wait`, polling the screen), `controls.ts` (`alert`/`home`/`back`/`rotate`/`appearance` over `createDevice`, `nextShotPath`), `flows-command.ts` (`record`/`replay`/`export`), `flow-sink.ts` (the `RecordSink`: each action → a `.flow.json` step with a durable selector chain, secrets by `WARDEN_UI_SECRET_*` name), `flow-actors.ts` (replay executor per step kind), `devtools-cli.ts` (`eval`/`tree`/`logs`/`network` against the dev client's Metro), `bench.ts` (`warden ui bench` against the plan's speed targets). Specs run through `e2e/bun-runner.ts` (`bun test --preload @delacour/warden-e2e/preload`; argv/env helpers that `commands/e2e.ts` wires into batch jobs).
- `hooks/`: agent hook handlers (`claude-pretool.ts`: SessionEnd + `deviceTarget`, shared by Claude Code and Codex: same stdin JSON; `warden hook pretool` is a hidden no-op for configs older versions wrote, and `install` removes that hook), hook-config merge (`claude-settings.ts` `mergeWardenHooks`; `codex-hooks.ts` for `$CODEX_HOME/hooks.json`), agent detection (`agents.ts`), text diff. Hook failures never block a tool (exit 0).
- `assets/assets.d.ts`: `*.md` text-import typing. The skill is the repo-root folder `skills/warden/` (`SKILL.md`, `references/*.md`, `rules/warden.md`), embedded via `src/skill.ts` (`SKILL_FILES`, `RULE_MD`); `warden install` stages the folder under `$WARDEN_HOME/skill/warden` and runs `bunx skills add … -g -a claude-code [-y]` (npx fallback; `skill-cli.ts` is shared with `warden skill install`; the step is `unchanged` when `~/.claude/skills/warden` is already current, `skipped` without bunx/npx) and writes the rule directly to `~/.claude/rules/warden.md`; `warden skill show --file <path>` prints one embedded file.
- `warden install` targets detected agents (or `--claude` / `--codex`) and never touches `~/.claude` / `~/.codex` without showing a diff + confirm (`--yes` / `--dry-run`); tests use a temp `HOME` (detection reads `ctx.env.PATH`, never the process PATH).
- `update/`: build info (`dev`/`local`/`release`, embedded via `--define __WARDEN_BUILD__=<json>`), semver, GitHub release lookup/download (gh), source build, atomic binary install with self-check, npm install detection (`package-install.ts`: npx / bunx / npm / bun / pnpm global / project, read off the binary's `node_modules/@delacour/warden-<target>/` path → `update` prints the upgrade command, `install` links global installs instead of copying). npx/bunx copies are recorded in `$WARDEN_HOME/install-origin.json` (`install-origin.ts`) and update from the npm registry (`npm-registry.ts`: latest → platform tarball → sha512 integrity → `tar.ts` extract), which is also the fallback when GitHub releases can't be reached.
- `npm/`: the npm distribution. `platforms.ts` (release targets, package names), `manifests.ts` (generated `package.json`s), `shim.ts` + `shim-main.ts` (the node `warden` bin that runs the platform package's binary; bundled for node, so node APIs only). `config-entry.ts` emits `@delacour/warden/config` (`config/index.{mjs,d.ts}`) from core `builds/define-config.ts`. `helper.ts` / `helper-stage.ts` / `helper-asset.ts`: the iOS driver helper `warden-simd` (built by `packages/e2e` `native:build` into `native/dist`) — staged into `@delacour/warden-darwin-arm64/bin/` (`warden-simd`, `Resources/`, `*.framework`, `manifest.json`; `warden.helper` + a `bin` entry in its package.json; other targets get none) and packed as the `warden-simd-darwin-arm64.tgz` + `SHA256SUMS` release assets. `update/fetch-helper.ts` (`warden doctor --fetch-helper`) downloads that tarball (sha256-checked) into `$WARDEN_HOME/simd/<version>/`; `commands/doctor-helper.ts` is the doctor `sim-helper` / `sim-helper-health` rows (locate via `@delacour/warden-e2e/driver/ios/locate-helper`, then `warden-simd --health`).

## Build
- `bun run build` → `dist/warden` (channel `local`, records this checkout; `scripts/build.ts`)
- `bun run build:release` → `dist/warden-{darwin,linux}-{arm64,x64}` + `checksums.txt` (CI, on `v*` tags)
- `bun run build:npm` (after `build:release`) → `dist/npm/warden-<target>/` (`@delacour/warden-<target>`: binary, `os`/`cpu` pinned) + `dist/npm/warden/` (`@delacour/warden`: node shim bin + exact-version optionalDependencies). On darwin-arm64 the platform package also carries the helper from `packages/e2e/native/dist` when built (`--require-helper`, used by the release, makes a missing one an error; `WARDEN_E2E_NATIVE_DIST` overrides the dir). `bun run build:helper-asset` (after `build:release`) writes `dist/warden-simd-darwin-arm64.tgz` + `dist/SHA256SUMS`. The release workflow publishes them; this `package.json` stays `private` because the published manifest is generated.
- `bun run install:global` = `bun src/cli.ts update` → `~/.local/bin/warden`
- `bun run cli:link` (repo root; `bun run link` here) → `~/.local/bin/warden` becomes the `install --shim` shim to this checkout's `src/cli.ts`: live source, no build, hooks/skill untouched. `bun run cli:unlink` restores rather than removes: `scripts/link/state.ts` snapshots the entry first into `~/.local/bin/.warden-link.json`, moving a real binary aside to `.warden-link-backup`, and puts back the binary, the symlink or nothing. The snapshot is machine-wide, so a second `cli:link` (any worktree) keeps the first one. With no snapshot, only a shim to this checkout is removed. `warden update` while linked compiles a real binary over the shim; `cli:unlink` then leaves it and drops the snapshot + backup.
- Never compile without `scripts/build.ts` / `compileArgs` — a binary without build info can't update itself.
- `compileArgs` passes `--minify --bytecode --sourcemap=linked`: a cold `warden version` is ~27 ms instead of ~120 ms (the plain binary re-parses the 10 MB bundle on every start), the source map is embedded so stack traces and uncaught-error excerpts stay readable, and the binary is ~1.5× bigger. Bytecode bundles as CommonJS: no top-level `await` anywhere in the CLI's import graph (`cli.ts` uses `.then`; `source-build.test.ts` bundles it to catch one). Bun also leaves a loose `cli.js.map` beside the outfile, which `scripts/build.ts` deletes.
